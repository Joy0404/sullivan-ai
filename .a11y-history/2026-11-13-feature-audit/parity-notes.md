## 원본도 제공하지 않던 기능을 구분

- 원본의 ‘현재 화면 다시 설명’은 실시간 새 화면 분석이 아니라 준비된 설명 재생이었다. 이를 확장 기능 누락으로 분류하면 안 된다. 새 프레임 분석을 원하면 별도 기능 범위와 동의·지연·공급자·확신도 정책이 필요하다.
- 원본의 보호자→학생 파일 인계는 같은 브라우저·프로필·웹 출처의 저장소를 공유했기 때문에 가능했다. 다른 기기로 파일을 자동 배포하는 구현 근거는 없다. 두 독립 확장의 IndexedDB는 출처가 달라 그대로 공유되지 않는다.
- 원본 현재 `apps/web/app.js:312`도 실제 파일 분석에서 전송 동의를 요구한다. 유료 공급자 없이 원본 영상을 자동 분석할 수 있었다고 주장하면 안 된다.
- DRM 우회·보호 스트림 다운로드는 원본에서도 의도적으로 미지원이다. 확장의 `video-control.js:10`도 DRM `mediaKeys`를 거부한다.

## 구현과 실행 지원의 구분

검사에서 확인한 것은 함수·라우트·UI·자료 계약의 존재와 호출 관계다. 코드에 있는 Gemini 분석, 링크 분석, 음성 인식, 설치 음성, 원본 사이트 제어가 특정 환경에서 지금 성공한다는 검증 결과는 아니다. `docs/FEATURE_STATUS.md`의 동작/조건부 동작 표기는 기존 원본의 상태 문서이며 확장의 모든 기능을 시험했다는 뜻도 아니다.

다음 구현 우선순위는 개념 구간 연속 재생, 보호자 미리보기, 명시적 원본 전달, 복습 본문·범주 복구, 탐색 복귀 일원화다. 원본 전달에서는 기본 서버 보관을 추가하지 않고, 사용자 동의와 준비 상태 확인을 가진 전달 방식을 먼저 선택해야 한다.
