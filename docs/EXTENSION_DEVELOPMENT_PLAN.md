# 두 확장 프로그램 개발 계획

2026-11-12. 기존 기능의 보존을 전제로 단계별로 구현한다. 계획의 완료와 제품 전체의 구현 완료를 구별한다.

## 구현 순서

1. 독립 설치·인증 기반과 첫 수직 흐름: 역할별 MV3 패키지, 별도 세션, 기존 계정 로그인, 보호자 학생 생성·샘플 배정, 학생 배정 목록·안전하게 정리된 자료 열람·진도/메모 저장. 실제 Chrome에서 같은 프로필의 동시 로그인·개별 로그아웃을 검증한다.
2. 준비 기능 이전: 자막·지문·분석 JSON·실제 분석, 배정 편집·회수·순서·학생 설정·진도 확인. 기존 공급자와 안전 코어를 재사용한다. 분석 작업의 영속 저장과 재시작 복구를 구현한다.
3. 수강 기능 이전: 원본 강의 탭 어댑터·재생/해설 동기화, 로컬 파일 연결, 기존 지문·개념 탐색·학습 대화·복습·북마크·밑줄, 음성·타자·단축키·설정. 원본 파일 공유를 자동이라고 표시하지 않는다.
4. 계정과 운영 전환: 일회용 연결 코드·학생 확인·연결 해제, 운영용 가입·복구와 표준 인증, 영속 작업·데이터 이전·버전 호환·장애 복구, 실제 VoiceOver/NVDA 검증과 두 스토어 배포.

각 단계는 기존 웹을 계속 실행 가능하게 유지한다. 미이전 기능은 삭제하지 않고 기존 웹에 유지하며, 확장에서 이용 가능한 기능을 명시한다. 기능 대응표의 모든 항목을 검증한 뒤 기존 웹의 종료 여부를 결정한다.

## 1단계 범위와 설계

- 개발용 서버는 기존 로컬 서버를 사용한다. SQLite 계정·배정·진도를 공유하고, 확장 세션은 별도 테이블에 해시만 저장한다.
- 학생·보호자 토큰은 역할 클라이언트에 묶는다. 쿠키 인증은 기존 웹 전용으로 유지한다. 인증 헤더가 있으면 잘못된 토큰을 웹 쿠키로 대체하지 않는다.
- 확장 토큰은 `chrome.storage.session`에만 보관한다. 브라우저 재시작 시 다시 로그인한다. 운영용 PKCE·갱신 토큰·계정 복구는 4단계에서 구현하며 현재 구현이라고 표시하지 않는다.
- 로컬 개발 신규 보호자 가입만 제공한다. 운영 서버의 가입은 기본 비활성화다. 기존 보호자·학생 계정으로 로그인 가능하다.
- 각 패키지는 자기 역할 UI와 공통 통신 코드만 포함한다. 학생은 사이드 패널, 보호자는 전체 탭을 연다. 배포물은 `dist/extensions/student`, `dist/extensions/guardian`이다.
- 초기 패키지는 서버 호스트와 storage 권한만 요청하고 학생용에만 sidePanel 권한을 추가한다. 사이트 제어·마이크·캡처는 구현 시 필요한 범위로 별도 추가한다.
- 샘플은 사전 준비 데이터임을 표시한다. 학생 초기 화면의 자료 열람을 실제 영상 재생·실시간 분석이라고 표현하지 않는다.

## 검증과 완료 조건

1단계는 서로 다른 확장 ID로 같은 프로필에 설치하고, 보호자가 학생을 생성·배정한 후 학생이 열람·저장할 수 있어야 완료다. 보호자 로그아웃 후 학생은 계속 이용 가능해야 한다. 다른 역할 토큰·다른 보호자의 자료·만료 또는 폐기 토큰은 서버가 차단해야 한다. 기존 웹 인증·테스트를 통과하고 패키지에 상대 역할 화면이 없어야 한다.

후속 단계에서 미지원 기능을 지원했다고 표시하지 않는다. 1단계 완료는 전체 확장 전환 완료나 스토어 출시 준비 완료를 뜻하지 않는다.

## 2026-11-12 구현 결과

1단계를 구현했다. 독립 세션 API와 역할별 패키지, 보호자 학생 생성·샘플 배정, 학생 준비 자료 열람·브라우저 음성 요청·메모/위치 저장을 추가했다. 학생의 기존 북마크·밑줄을 저장 요청에서 보존한다. 기존 웹 화면·Gemini 설정·쿠키 로그인은 유지했다.

- 전체 검증: API 127개 통과·4개 건너뜀, 패키지 경계 검사 2개 통과, 기존 JS 기능·구문·정적 검사 통과.
- 실제 Chromium 156에 두 MV3 패키지를 같은 임시 프로필에 설치해 동시 로그인, 배정·열람·저장·재접속 복원, 보호자 단독 로그아웃, 다른 역할 로그인 차단을 확인했다.
- 390px·1280px 화면, 본문 건너뛰기와 저장/오류 후 초점을 확인했다. 폼·키보드 전문 검토에서 발견한 4개 항목은 수정했다.
- 실제 스크린리더 음성·한국어 TTS 청취 품질·외부 플레이어·사이트 호환성은 아직 검증하지 않았다. 전체 WCAG 준수나 완전한 기능 이전을 주장하지 않는다.

## 2단계 구현 결과

보호자 확장에 자막·지문·표준 분석 JSON 준비, 링크 등록·동의한 실제 링크 분석, 별도 동의한 원본 파일 분석을 연결했다. 모델·호출·이용 코드·횟수 제한·공급자 및 임시 원본 삭제 처리는 기존 분석 경로를 재사용한다. 준비 상태는 접수·진행·완료·실패·중단으로 구별한다. 실패나 연결 미설정을 분석 성공으로 표시하지 않는다.

준비 작업과 검증된 결과는 계정 DB에 저장한다. 완료한 결과는 메모리 세션 없이도 확인·배정할 수 있다. 진행 중 작업은 서버 재시작 시 중단으로 표시하며, 비용이 드는 분석이나 원본 업로드를 자동 재실행하지 않는다. 보호자가 자료와 동의를 다시 선택해 새 작업을 요청한다. 현재 작업 실행기는 단일 서버 프로세스용이며, 다중 워커·분산 큐는 운영 전환 범위다.

준비 결과 확인 후 여러 학생에게 배정할 수 있고, 같은 결과의 배정 요청 재전송은 동일 강의를 반환한다. 강의 제목·과목·배정 학생 수정, 전체 배정 회수와 재공개, 학생별 강의 순서, 학생 기본 설정, 진도·기록 수 요약을 제공한다. 회수는 원본 자료와 개인 기록을 삭제하지 않는다. 보호자에게 메모 원문을 추가로 공개하지 않는다.

검증 결과:

- API 137개 통과·4개 건너뜀, 패키지 경계 2개와 기존 JS·정적 검사 통과.
- 실제 두 확장에서 자료 준비→결과 확인→배정→학생 열람, 설정·편집·순서·확인 후 회수 통과. 보호자 탭을 닫고 다시 연 뒤 준비 결과를 복원했다.
- 별도 서버 프로세스를 실제로 두 번 재시작하여 완료 자료 배정과 강제 종료한 지연 작업의 중단 복구를 확인했다. 지연은 검사 전용으로 주입했으며 유료 호출은 없다.
- 기존 분석 어댑터 호출은 모의 공급자로 검증했다. 동의 미제공·키 미설정·삭제 실패에서 실패 처리하고, 임시 원본의 정상 경로 삭제 및 코드·원본의 DB 비저장을 확인했다.
- 390px·1280px 화면과 키보드 동작 확인. axe-core 4.14.0의 WCAG A/AA 태그 검사에서 확인한 5개 화면의 위반 0건. 폼·키보드·상태 안내 전문 검토의 지적 사항 수정 완료.

실제 Gemini 호출·청취 음질·VoiceOver/NVDA·외부 강의 플레이어·원본 분석 중 비정상 프로세스 종료 시 공급자 삭제는 미검증이다. 원본 파일의 학생 기기 전달 기능은 아직 제공하지 않는다.

## 3단계 구현 결과

학생 확장 0.3에 다음을 구현했다. 실제 사이트·보조기기 검증이 끝난 출시 버전이라는 뜻은 아니다.

- 학생 사이드 패널과 전체 수강 탭, 최근 강의와 저장 위치 복원.
- 원본 탭의 표준 HTML 영상 조작: 재생·전체 중지·10초 이동·탐색 전 위치 복귀. YouTube watch 주소는 영상 ID로, 직접 링크는 주소로 일치 여부를 검사한다. 현재 탭 연결은 사이드 패널 사용을 기준으로 한다.
- 파일 직접 선택과 SHA-256·크기 대조. 0.3에서 새로 준비한 원본 파일은 서버가 분석 때 식별 정보만 저장하고 학생이 선택한 원본과 비교한다. 학생 파일은 업로드하지 않는다.
- 일치한 파일의 재생, 준비된 시점 자막과 자막 표시 버튼, 영상 음량·음소거. 원본 식별 정보가 없는 기존 파일은 수동 재생·자료 읽기를 제공하고 자동 해설을 켜지 않는다. 자동 해설을 사용하려면 식별 정보를 포함해 다시 준비한다.
- 검증된 설명의 시점 감지 → 정지 → 앱 음성 → 이전에 재생 중이었을 때만 재개. 광고·길이를 확인할 수 없는 실시간 영상·식별하지 못한 파일에는 자동 해설을 적용하지 않는다. 현재 화면을 새로 캡처·분석하는 기능은 추가하지 않았다.
- 지문 전체·문단·문장·강조·밑줄 탐색, 개념 검색과 강사 구간 이동, 복습·개념 지도·용어·확인 질문, 북마크·메모·밑줄 저장, 학습 노트 내보내기.
- 기존 명령 분류·Space 처리·탐색·해설 스케줄러·맥락 설명 모듈을 재사용한다. 기존 학습 응답 함수만 빌드에서 추출해 추가 학습 도구를 유지하며 보호자 화면 코드는 학생 패키지에 넣지 않는다.
- 기존 학생 학습 대화 API 연결과 제한적 자료 기반 응답의 구분. 낮은 확신도 응답은 보류한다. 질문 중지·강의 전환·로그아웃·재생 소유 화면 변경 뒤의 늦은 응답은 실행하지 않는다.
- 명시적 동의가 있는 브라우저 음성 인식과 타자 대체. 선택형 Space 길게·두 번·세 번, 선택형 Shift 이전 이동, Chrome 패널/중지 단축키. 입력칸과 외부 강의 사이트의 기본 키는 보존한다.
- 학생의 속도·앱 음량·자동 해설·스크린리더·초점 안내 설정. 설치된 한국어 음성 선택과 음높이·키보드 설정은 기기별 계정 설정으로 저장한다. 문제 보호 정책은 학생 설정 API로 변경할 수 없다.
- 명시적으로 선택한 100MB 이하 원본의 계정·강의별 AES-GCM 암호화 보관·재열기·사본 삭제. 로그인과 현재 배정 확인이 필요하며 다른 브라우저·다른 기기로 원본을 자동 전달하지 않는다.
- 한 학습 화면의 영상·음성 소유권, 중지 세대와 재생 요청 순서 검사, 외부 탭의 4초 연결 확인 타이머. 패널을 닫거나 연결을 잃으면 제어 중인 영상을 정지하는 방향으로 실패 처리한다. 작업 상태를 서비스 워커 메모리에만 의존하지 않는다.

권한은 학생 확장에만 `scripting`, `activeTab`을 추가했다. 원본 사이트는 연결 버튼을 누를 때 해당 출처의 선택 권한을 요청한다. 모든 사이트 접근을 설치 때 일괄 허용하지 않는다. 콘텐츠 스크립트에는 영상 조작과 상태 확인만 보내며, 계정·토큰·API 요청을 넘기지 않는다. 교차 출처 iframe·DRM 플레이어는 지원 대상으로 확정하지 않았다.

검증 결과:

- API 139개 통과·4개 건너뜀. 패키지 경계 검사, 기존 JS 기능 검사, 새 음성 취소·늦은 완료·연속 초점·스크린리더 모드·미지원 플레이어 결과 검사 통과.
- 실제 Chromium에 두 확장을 설치하고 실제로 디코딩되는 생성 MP4로 파일 식별·다른 파일 거부·재생·이동·자막·시점 해설·중지·암호화 보관과 복원을 확인했다. 학생의 원본 업로드는 발생하지 않았다.
- 브라우저의 실제 HTML 영상 탭으로 격리된 제어와 수강 화면 종료 뒤 정지를 확인했다. 이 탭은 검사 전용 서버 페이지로, 실제 YouTube 호환성 검사와 구분한다.
- Space와 타자 창, 북마크·밑줄·개념 검색·학습 도구·내보내기, 다른 수강 화면으로 전환할 때 늦은 질문 응답·음성이 실행되지 않음을 확인했다. 음성 합성과 공급자 응답은 명시적으로 모의 경계를 사용했다.
- 390px·1280px 화면 확인. axe-core 4.14.0에서 확인한 6개 화면의 WCAG A/AA 태그 위반 0건. 키보드·폼·미디어·모달·상태 안내 전문 검토의 지적 사항을 수정했다. 자동 점검을 실제 스크린리더 검증으로 간주하지 않는다.

남은 확인 사항은 실제 YouTube 및 대상 강의 사이트, 실제 브라우저 음성 인식, 사람이 듣는 한국어 음성 품질, VoiceOver/NVDA 전체 흐름이다. 브라우저/사이트의 자동 재생·권한 정책과 백그라운드 타이머 제한 때문에 연결이 중단되면 안내 후 재연결해야 한다. 기존 로컬 실행기의 Mac 시스템 첫 음성은 확장에 포함하지 않고 접근 가능한 로그인과 명시적 음성 시작으로 대체한다.

## 4단계 구현 결과와 출시 경계

계정·운영 기반을 0.4.0으로 구현했다. 4단계에 포함한 실제 VoiceOver/NVDA 검증과 두 스토어 공개는 미완료이며, 제품 전체의 출시 완료로 표시하지 않는다.

- 보호자·학생 독립 가입과 역할 고정, 일회용 연결 코드, 학생의 이름·공유 범위 확인 후 승인, 양쪽의 명시적 연결 해제. 해제 시 이전 보호자의 배정 이용·조회는 종료하고 개인 기록은 보존한다.
- Chrome identity 실제 팝업과 S256 PKCE, 정확한 역할별 클라이언트·반환 주소·state 검사, 짧은 액세스 자격과 30일 절대 기한의 회전 갱신 자격. 재사용은 해당 로그인 계열을 폐기한다.
- 일회용 복구 코드 8개·현재 비밀번호 재확인 후 재발급, 코드 복구 시 기존 로그인 전체 종료, 내 로그인 계열 확인·개별 폐기·전체 로그아웃. 이메일 자동 복구는 제공하지 않는다.
- 사용자가 선택한 로그인 유지, 역할별 운영 초대 가입, HTTPS·등록 ID·영속 볼륨·단일 프로세스 시작 검사, 프로세스 중복 실행 차단, 최소 확장 버전 호환 검사.
- 원본 DB를 덮어쓰지 않는 복사 이전·무결성/행 수 대조·세션 폐기 도구, 이전 DB와 코드로 원복하는 절차. 실제 사용자 DB의 운영 이전은 수행하지 않았다.
- 역할별 아이콘과 독립 ZIP·SHA256 목록, GitHub의 누적 브라우저·재시작·운영 설정 검사. 패키지 생성은 스토어 자동 공개가 아니다.

검증: API 150개 통과·4개 건너뜀, 패키지 경계·생성 JS 구문 검사 3개와 기존 JS 검사 통과. 실제 두 확장의 PKCE 로그인(실패 후 재시도 포함)·기억한 갱신 자격 복원·가입·코드 다운로드·연결 동의·배정·저장·해제·복구를 확인했다. axe-core 4.14.0은 확인한 10개 화면에서 WCAG A/AA 태그 위반 0건이며, 폼·키보드·상태 안내 전문 검토의 지적 사항을 수정했다. 별도 프로세스의 운영 설정 거부·시작과 실제 두 번의 준비 작업 재시작 검사도 통과했다. 실사용 음성·보조기기 검증과 구분한다.

검증 결과와 출시 전 필요한 실제 값은 [4단계 브라우저 결과](verification/extension-phase4-results.json), [운영 시작 검사](verification/extension-production-results.json), [운영·복구 안내](EXTENSION_OPERATIONS.md)를 참고한다. 실제 공개 HTTPS 서버·스토어 ID·개인정보/지원 URL·시험 계정 등록, 실제 사이트·음성·보조기기 검증이 남았다. 기존 웹은 계속 유지한다.
