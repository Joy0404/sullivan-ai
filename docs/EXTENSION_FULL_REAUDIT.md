# 전체 기능 재검사 결과

> 이 문서는 수정 전 **0.4.2 감사 기록**이다. 확인한 18건은 후속 로컬 0.4.3에서 수정하고 재현 회귀를 통과했다. 현재 상태는 [18건 수정 결과](EXTENSION_REAUDIT_FIXES.md)를 참고한다. 아래 실패 관찰과 판정은 이력을 위해 보존한다.

**판정: 출시 전 수정이 필요하다.** 로컬 0.4.2에서 기능 문제 **18건(높음 4·중간 12·낮음 2)**을 실제 확장 문서에서 확인했다. 우선 수정할 문제는 다른 강의의 영상 연결, 다른 강의의 진도 덮어쓰기, 안내 중 뒤늦은 재생, 앱 음성의 연결 오류 안내 누락이다.

검사 기간: 2026-11-13~14. 대상 작업 폴더는 `Sullivan-AI-Develop-local`의 커밋 전 로컬 작업본이다. 이번 재검사에서는 실행 제품 소스를 보존하고 검사 도구·관찰값·보고서를 작성했다. 실행 제품 파일의 시작·종료 해시가 일치하며, 안내 문서인 확장 README의 수정은 별도로 기록했다. 실제 사용자 DB와 유료 공급자 자격을 사용하지 않았다.

## 우선 수정할 4건

| 번호 | 재현한 문제 | 영향과 확인값 |
| --- | --- | --- |
| R01 | 강의 A의 원본 연결 권한을 기다리는 동안 강의 B를 열고 권한을 완료하면 A 영상이 B에 연결됨 | B의 정상 원본은 YouTube인데 실제 worker의 연결 URL은 A의 시험용 원본이었다. 다른 강의의 화면·해설이 결합할 수 있다. |
| R02 | 강의 A의 구간 이동 응답을 기다리는 동안 B를 연 뒤 A 응답이 완료되면 B의 위치를 저장함 | B의 서버 저장 위치가 **42,000ms → 8,000ms**로 변경됐다. B의 `/progress`에 잘못된 PUT이 실제 전송·저장됐다. |
| R03 | 재생 응답이 늦게 도착하는 동안 새 항목의 음성 안내가 시작되면 영상이 다시 재생됨 | 안내를 끝내지 않은 상태에서 `paused=true → false`로 바뀌었다. 안내와 영상 소리가 겹칠 수 있다. |
| R04 | 원본 탭 종료·다른 수강 화면의 재생권 취득으로 영상이 중단돼도 앱 음성으로 이유를 안내하지 않음 | 화면의 연결 문구는 바뀌었으나 합성 요청·상태 이벤트는 모두 비어 있었다. 외부 스크린리더 없이 앱 안내를 쓰는 학생이 중단 이유를 듣지 못한다. |

R01·R02는 실제 서버·DB·worker·디코딩 영상에 권한 또는 응답 완료만 지연시켜 확인했다. R03의 영상은 실제 MP4이며 음성 합성은 완료를 보류하는 시험 장치다. R04는 실제 원본 탭 종료와 다른 확장 문서의 재생권 취득으로 확인했다. 실제 OS 스크린리더나 사람이 듣는 음성 검사를 했다는 뜻은 아니다.

근거: [강의 전환 경합](../.a11y-history/2026-11-13-full-reaudit/runtime-keyboard/results.json), [재생·초점 추가 검사](verification/2026-11-13-full-reaudit/supplement/observations.json), [연결·음성 모드 검사](../.a11y-history/2026-11-13-full-reaudit/runtime-live/observations.json).

수정할 때는 권한 요청·구간 이동·재생 완료 **이후에도** 시작 당시의 강의·화면·작업이 유효한지 검사해야 한다. 저장은 시작 때 선택한 강의에 묶고, 새 안내가 소유한 정지를 오래된 재생이 해제하지 못하게 해야 한다.

## 기존 웹 검사 실패의 분리 진단

기존 웹 관련 스크립트 등 11개를 그대로 실행한 첫 결과는 **7개 통과·4개 실패**다. 원본 실패 로그를 보존했다. 기존 웹 소스는 원본 기준 `888a026`과 같으며 이번 감사에서도 변경하지 않았다.

- `verify_roles_browser.py`: 지연되는 Space 단일 입력과 비동기 밑줄 저장을 즉시 단정했다. 진단용 복사본에서 같은 결과를 조건 대기로 확인한 뒤 전체 흐름이 통과했다.
- `verify_voice_preferences.py`: 상태 안내 갱신을 240ms 뒤 즉시 단정했다. 진단 복사본에서 대기 시간을 늘려 같은 기대값을 검사한 전체 흐름은 통과했다. 상용 검사에는 고정 지연보다 상태 조건 대기가 적합하다.
- `verify_audio_navigation.py`: 닫힌 샘플 영역 안의 버튼을 바로 실행하려 했다. 진단 복사본에서 영역을 연 뒤 같은 전체 흐름은 통과했다.
- `verify_login_assignment.py`: API로 추가한 대기 자료를 갱신하지 않은 목록에서 찾고 닫힌 `관리` 안의 버튼을 찾았다. 목록을 다시 불러오고 관리를 연 **별도 해당 구간 검사**는 통과했다. 원본 전체 스크립트의 통과로 바꾸어 기록하지 않았다.

[원본 실행 목록](verification/2026-11-13-full-reaudit/service-web-results.json), [진단 복사본 결과](verification/2026-11-13-full-reaudit/legacy-adjudication.json), [대기 자료 구간 결과](verification/2026-11-13-full-reaudit/targeted-legacy-draft-recovery.json). 제품과 기존 검사 파일을 수정해서 통과시킨 결과가 아니다.

기존 적용 확인 59개에서 추가 경계 오류와 초점 문제에 연결된 항목을 부분 적용으로 조정했다. 저장 실패·오프라인 복구 F56은 이번 실제 재시도 검사로 적용 확인으로 올렸다. 미적용 0은 기능 코드가 없던 항목을 구현했다는 뜻이며 무결함·출시 완료 판정은 아니다.

[78개 전체 상태·근거](verification/2026-11-13-full-reaudit/feature-inventory.json)에는 이전 판정과 이번 문제 번호를 함께 남겼다. 대시보드 세부 단계, 공급자 내부 진행률, 원본 자동 인계의 기존 축소도 계속 기록한다.

실제 VoiceOver/NVDA 낭독, 실제 마이크 서비스, 사람이 듣는 한국어 음질, 실제 Gemini·외부 분석 공급자의 결과 품질, 실제 YouTube/대상 사이트, 모든 OS·코덱 조합은 이번 검사에서 확인하지 못했다. 실제 사용자 DB·유료 자격을 써서 이 항목들을 통과로 표시하지 않았다.
