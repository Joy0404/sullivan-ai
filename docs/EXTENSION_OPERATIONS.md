# 두 확장 프로그램 운영·복구 안내

0.4.0의 운영 기반은 구현했다. 운영 서버 배포와 Chrome Web Store의 실제 등록·공개는 아직 수행하지 않았다. 기존 웹을 종료하지 않으며 기존 계정·강의·배정·개인 기록을 유지한다.

## 계정과 연결

학생·보호자는 각각 자기 확장에서 독립 가입한다. 가입 시 복구 코드 8개를 한 번 표시하며 다운로드한 코드는 비밀번호처럼 보관한다. 기존 계정은 비밀번호를 확인해 복구 코드를 발급할 수 있다. 복구 코드를 모두 잃은 경우 자동 이메일 복구는 제공하지 않는다. 운영자 확인 후 별도의 복구 절차가 필요하다.

보호자가 10분짜리 일회용 코드를 전달하면 학생이 보호자 이름과 공유 범위를 확인하고 명시적으로 승인한다. 코드 입력만으로 연결하지 않는다. 한 학생은 현재 보호자 한 명과 연결한다. 기존 연결은 그대로 유지하며 다른 보호자로 자동 교체하지 않는다. 학생 또는 보호자가 확인 후 연결을 해제하면 해당 보호자의 배정 이용과 이후 조회 권한이 끝난다. 개인 기록은 삭제하지 않는다. 다시 연결해도 강의를 다시 배정해야 한다.

운영 로그인은 Chrome identity 창과 S256 PKCE 코드 교환을 사용한다. 등록한 확장 ID와 정확한 반환 주소만 허용한다. 액세스 자격은 15분, 갱신 자격의 절대 수명은 30일이다. 갱신 때 회전하며 사용한 갱신 자격의 재사용은 해당 로그인 계열을 종료한다. 다른 역할·다른 계정의 세션은 종료하지 않는다. 내 계정에서 로그인 목록·개별 종료·전체 로그아웃을 제공한다. 목록은 로그인 계열이며 물리적 기기 이름을 수집하는 기능은 아니다.

기본 로그인 정보는 `chrome.storage.session`에 보관한다. 사용자가 ‘내 기기 로그인 유지’를 선택한 경우에만 갱신 자격을 확장 전용 로컬 저장소에 보관한다. 로그아웃은 서버 자격과 로컬 기억을 폐기한다. 원본 보관 사본 삭제는 별도 기능이다.

## 운영 서버 준비

1. 실제 HTTPS 서버 출처, 서로 다른 두 확장 ID, 단일 프로세스와 영속 디스크를 준비한다. 임시 컨테이너 파일 시스템에 실제 계정 DB를 두지 않는다.
2. [운영 환경 변수 예시](../deploy/extension.env.example)를 서버의 비공개 설정에 옮기고 실제 값으로 교체한다. API 키와 초대 코드는 저장소나 확장 빌드에 넣지 않는다. 가입 초대 코드를 비워 두면 신규 가입은 닫힌다.
3. DB 부모 디렉터리를 서버 사용자에게만 쓰기 가능하게 연결한다. 컨테이너 사용자는 UID 10001이며 `/app/data/private`를 영속 볼륨으로 연결한다. HTTPS 역방향 프록시는 별도로 구성한다. `SULLIVAN_PUBLIC_URL`은 로그인 폼 Origin 검사에 쓰인다.
4. 같은 환경에서 `python scripts/check_extension_deployment.py`를 실행한다. 누락된 설정, 잘못된 ID, 다중 워커를 거부한다. 서버도 시작 시 같은 검사를 수행하고 DB 옆 프로세스 잠금으로 중복 실행을 거부한다.
5. 최소 버전을 올리기 전에 두 패키지를 먼저 배포한다. 이전 버전은 426으로 업데이트 안내를 받는다. `/extension/v1/{role}/capabilities`는 프로토콜·최소 버전·가입 가능 여부를 반환한다.

현재 SQLite와 준비 작업 실행기는 서버 프로세스 하나만 지원한다. 분산 작업 큐나 무중단 다중 서버 전환을 구현했다고 주장하지 않는다. 프로세스 재시작 시 진행 중 분석은 중단으로 표시하고 비용이 드는 분석을 자동 재실행하지 않는다. 완료 결과는 다시 배정할 수 있다.

## 데이터 이전·원복

실제 전환 때는 쓰기를 멈추고 서버를 종료한 뒤 진행한다. 원본 DB는 덮어쓰지 않는다. 다음 경로는 예시이며 실제 DB 위치를 먼저 확인한다.

```bash
python scripts/manage_extension_data.py check /private/current/accounts.sqlite
python scripts/manage_extension_data.py backup /private/current/accounts.sqlite /private/backups/before-04.sqlite
python scripts/manage_extension_data.py migrate /private/current/accounts.sqlite /private/new/accounts.sqlite
```

SQLite backup API로 일관된 복사본을 만들고 무결성·참조 관계·주요 테이블 행 수를 대조한다. 기존 ID·강의·배정·개인 기록을 유지하고, 이전 대상의 세션·미사용 인증 코드·연결 코드는 폐기한다. 새 DB 경로로 서버를 실행하고 가입·역할별 로그인·배정·저장·연결 해제를 확인한다. 문제가 생기면 새 서버를 정지하고 보존한 기존 코드와 이전 DB 경로로 복귀한다. 새 서버에서 추가된 기록은 자동 역이전하지 않으므로 원복 전에 별도로 보존·대조해야 한다.

계정 DB의 암호화 백업·보관 기간·복구 연습은 실제 운영 저장소에서 설정해야 한다. 이 도구는 자동 원격 백업 서비스가 아니다. 이번 개발에서는 실제 사용자 DB를 운영 서버로 이전하지 않았다.

## 패키지와 스토어 제출

```bash
python scripts/package_extensions.py
python scripts/package_extensions.py --release --server https://YOUR_REAL_SERVER
```

학생·보호자 ZIP과 SHA256 목록을 `dist/releases/0.4.0`에 생성한다. 첫 명령의 ZIP은 로컬 개발용이며 스토어 제출용이 아니다. `--release`는 실제 HTTPS 출처를 요구하지만 자동 제출·공개하지 않는다. 두 항목을 초안으로 등록하고 ID를 서버에 등록한 뒤 같은 ID로 갱신한다. 압축해제 개발 설치 ID와 스토어 ID가 다를 수 있으므로 별도로 확인한다.

제출 전 필요한 실제 값과 검증:

- 학생용·보호자용 별도 항목, 공개 개인정보 처리방침·지원 URL·개발자 연락처, 각 역할의 설명·스크린샷.
- 검사자가 사용할 두 역할의 시험 계정, 연결 코드 발급·동의·해제 절차, 유료 공급자 없이 실행할 샘플.
- 실제 운영 HTTPS 로그인·초대 가입·복구·세션 종료, 실제 대상 강의 사이트, 음성 인식과 한국어 음질, VoiceOver/NVDA의 전체 흐름 확인.
- 서버 저장 데이터와 원본 분석 전송·삭제, 브라우저 음성 서비스, 기기 내 원본 보관에 관한 실제 운영 정책 확정.

권한 설명: 공통 `storage`는 세션·설정, `identity`는 사용자가 시작하는 로그인 창, 서버 호스트 권한은 공통 API 연결이다. 학생 전용 `sidePanel`, `activeTab`, `scripting`은 학습 패널과 명시적으로 연결한 표준 영상 제어다. 사이트 출처 권한은 연결할 때 선택적으로 요청한다. 콘텐츠 스크립트에 계정 토큰을 보내지 않는다. 마이크는 브라우저 음성 인식 동의를 별도로 받으며 화면·탭 오디오 캡처 권한은 요청하지 않는다.

## 개인정보 안내 초안

서버에는 계정 식별 정보, 해시한 비밀번호·인증 자격·복구 코드, 보호자 연결, 준비된 분석 자료·식별 정보, 배정·학습 위치·개인 기록·설정을 저장한다. 보호자에게 메모·질문 원문을 제공하지 않는다. 학생 기기의 원본 파일은 업로드하지 않는다. 보호자의 실제 원본 분석은 기존 동의·임시 공급자 처리 경로를 사용한다. 해당 공급자의 비정상 종료 시 원본 삭제까지 검증한 상태는 아니다.

사용자가 선택한 원본의 브라우저 사본은 계정·강의별 AES-GCM 보관이며 같은 Chrome 프로필에 키도 저장한다. 이는 기기 침해에 대한 보호를 보장하지 않는다. 직접 사본을 삭제할 수 있다. 질문은 해당 기능을 사용할 때 서버의 학습 공급자로, 음성은 동의 후 브라우저 음성 서비스로 전송될 수 있다. 판매·광고·추적 용도는 구현하지 않았다.

이 절은 현재 코드의 데이터 흐름 설명 초안이다. 실제 운영자의 신원·연락처·보관 기간·계정 삭제 및 권리 행사 방법을 확정하고 공개 URL로 게시한 개인정보 처리방침을 대체하지 않는다.
