# 반복 누락 보고의 원인과 0.4.5 조치

2026-11-14. 이 문서와 [기능 기준표](extension-feature-contract.json)를 현재 판단 기준으로 사용한다. 이전 감사 문서는 당시 기록으로 보존한다.

## 원인

| 원인 | 실제로 생긴 일 | 조치 |
| --- | --- | --- |
| 구현 차이·설계 변경·검증 대기를 같은 ‘부분 적용’으로 집계 | 기존 4개 항목을 매번 다시 보고해 새 누락이 계속 발생한 것처럼 전달했다. | 구현 상태와 검증 상태를 별도 필드로 분리했다. 과거 판정과 제한 설명은 삭제하지 않았다. |
| 단계 대시보드를 작업 검색으로 대체한 채 원본 대응을 닫지 않음 | 준비 작업 검색은 추가했지만 학생·자료·배정·설정별 단계표 F16은 여전히 빠져 있었다. | 원본 상태 규칙과 단계별 이동 링크를 복원하고 6개 상태 전환·초점 회귀를 추가했다. |
| 수정 건수의 통과를 전체 기능 검증과 혼동 | 17개·18개 회귀 통과는 해당 경계의 결과인데 전체 이전과 구분이 충분하지 않았다. | 78개 기능의 고정 ID·구현 소스·관련 회귀·제한을 하나의 기준표에서 관리한다. 구조 검사가 행동 검증을 대신한다고 표시하지 않는다. |
| 여러 검사 명령과 날짜별 결과가 분산됨 | 어떤 결과가 현재 코드 전체를 검사했는지 추적하기 어려웠다. | 단일 통합 명령이 모든 검사 결과를 한 폴더에 저장한다. 시작·종료 소스 지문이 다르거나 하위 검사가 실패하면 통과하지 않는다. |
| 미검증을 삭제 작업 전체의 무기한 중단 조건으로 취급 | 실제 앱이 사용하지 않는 JS 구성 도구도 정리하지 못했다. | 실환경 검증 대기는 그대로 유지하면서, 참조가 없는 도구만 제거하고 기능·공용 서버 경로는 보존한다. |

앞선 ‘검사 통과’는 확정한 오류의 수정 완료였고, 원본의 모든 기능·모든 외부 환경의 완료를 뜻하지 않았다. 이 차이를 명확히 전달하지 못한 것이 반복 보고의 원인이다.

## 실제 수정

보호자 확장에 학생 연결, 강의 자료 준비, 학생 배정, 학생별 설정의 단계 목록을 추가했다. 상태는 **완료·할 차례·아직·기본값**이며 실제 학생·강의·완료 작업·공개 배정·설정에서 계산한다. 준비됐지만 미배정인 자료는 ‘배정할 차례’로 표시하고, 완료 결과만 있으면 결과 목록으로 이동한다. 공개되지 않았거나 연결된 학생이 없는 배정을 완료라고 표시하지 않는다. 링크를 다시 만들지 않아 갱신 중 초점을 유지한다.

기존 4개 ‘부분 적용’의 현재 의미는 다음과 같다. 숫자를 없애기 위해 기능을 구현했다고 바꾸지 않았다.

| 항목 | 현재 판단 |
| --- | --- |
| F16 단계 대시보드 | 실제 구현 누락을 수정하고 상태 전환·키보드 회귀로 검사한다. |
| F23 상세 분석 진행 | 실제 서버 경계 메시지는 이미 구현돼 있다. 공급자 내부 음성·화면 진행률은 얻을 수 없으며, 추정 표시를 실제 분석 결과처럼 추가하지 않는다. 이 제한은 기준표에 유지한다. |
| F34 실제 사이트 재생 | 탭 제어 구현과 실제 사이트 호환 검증을 분리했다. 사이트 검증은 계속 대기다. |
| F36 원본 인계 | 승인된 분리 계획에서 원본은 별도 전달·학생 선택·식별 대조다. 자동 인계는 미구현이며 기존 웹과 완전히 같다고 주장하지 않는다. 해당 설계 차이를 명시적으로 기록한다. |

기존 외부 미검증 7개에 F34 사이트 호환을 더한 **8개의 실환경 확인은 그대로 남아 있다.** 이들은 자동 검사 통과만으로 닫히지 않는다. 원본 자동 인계까지 포함한 전체 동등성 또는 스토어 출시 준비 완료를 선언하지 않는다.

## 재발 방지

[기준표](extension-feature-contract.json)는 F01–F78을 고정한다. 항목 삭제·중복, 구현 미해결, 소스·관련 회귀 연결 누락, 필수 대시보드 구조 유실, 미검증 목록 불일치, 근거 없이 설계 변경으로 돌리는 행위와 출시 완료 표기를 구조 검사에서 거부한다. 잘못된 입력을 주입하는 부정 검사도 포함한다.

통합 검사는 다음을 순서대로 실행한다.

1. 기존 정적·JS 코어·API·패키지 검사와 기준표 검사
2. 단계 대시보드의 6개 상태 전환과 키보드 이동
3. 저장 복구 등 추가 회귀 17개
4. 기존 기능 복원 누적 회귀
5. R01–R18과 보조 관찰 30개
6. 긴 지문·저장 실패 미디어 보존 최적화 경계 4개
7. 준비 작업의 실제 프로세스 재시작 복구
8. 운영 설정 거부·시작 검사

Node·pytest·axe가 없으면 통합 검사를 통과 처리하지 않는다. 검사 도중 소스가 바뀌면 해당 실행의 결과를 실패로 남긴다. CI도 동일한 진입점을 사용한다. `release_ready`는 계속 `false`다.

```bash
PATH="$PWD/.venv/bin:$PATH" \
SULLIVAN_AXE_SOURCE=/path/to/axe.min.js \
.venv/bin/python scripts/verify_extensions.py
```

현재 환경에서는 ffmpeg 보조 모듈 경로로 `PYTHONPATH=/tmp/sullivan-video-test`도 사용했다. 일반 환경은 `scripts/requirements-extension-tests.txt` 설치와 Chromium·ffmpeg가 필요하다.

이번 실행의 원본 로그·판정은 [통합 결과](verification/2026-11-14-closure/acceptance/results.json)에 있다. 결과의 `source_sha256`는 검사 대상 코드의 지문이며 `contract.external_pending`은 남아 있는 실환경 확인 목록이다.

0.4.5 통합 실행은 **8개 검사 그룹 전부 통과**했고 시작·종료·산출물 생성 시 코드 지문이 일치했다. API 153 통과·PostgreSQL 실DB 4 건너뜀, 단계 전환 6개, 추가 회귀 17개, R01–R18과 보조 관찰 30개, 누적 기능 복원·최적화 경계·프로세스 재시작·운영 설정 검사를 확인했다. 화면의 axe 위반은 0건이며 390px·1280px 캡처를 저장했다. 키보드 전문 재검토의 미해결 지적은 0건이다. [접근성 검토](../.a11y-history/2026-11-14-closure/report.md), [최종 코드·정리 근거](verification/2026-11-14-closure/summary.json)를 함께 보관한다. 이 결과로 실제 스크린리더 청취나 유료 분석 품질까지 통과 처리하지 않는다.

## 코드 정리

- 앱·빌드·검사에서 호출되지 않는 `neon.ts`와 직접 의존성 `@neon/config`, `@neon/env`를 제거했다. 오프라인으로 lockfile을 재생성해 루트 포함 34개였던 항목을 루트 1개로 줄였다. 기존 설치 폴더나 사용자 설정·DB는 삭제하지 않았다.
- 단계 표시와 설정 폼이 동일한 기본 설정 상수를 사용하도록 중복을 제거했다.
- 학생 명령 처리에서 앞선 분기가 항상 처리하던 중복 ‘원래 위치 복귀’ 분기를 제거했다. 기존 복귀·재생 회귀를 유지한다.
- CI에 분산된 확장 검사 호출을 통합 진입점으로 교체하고, 산출물 버전 경로 하드코딩을 제거했다.

Render 설정·Docker·서버 실행기·PostgreSQL 드라이버·프록시 검증·사용량 제한은 실제 실행·CI 경로가 있어 보존했다. 이름에 Render가 있다는 이유로 삭제하지 않았다. 기존 웹·인증 계약·Gemini 호출 설정·문제 보호·원본 비전송 정책은 유지한다.

## 적용

로컬 패키지는 0.4.5다. `scripts/build_extensions.py`, `scripts/package_extensions.py`로 생성하며 Chrome에서 두 확장을 새로고침하고 기존 확장 탭·패널을 다시 연다. 실제 서비스 배포나 스토어 게시는 수행하지 않는다.
