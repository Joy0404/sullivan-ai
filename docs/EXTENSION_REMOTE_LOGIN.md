# 보호자가 시작하는 학생 로그인 — 0.4.8

학생이 처음 한 번 가입·로그인하고 보호자 연결과 기기 로그인 지원을 승인하면, 다음부터 보호자가 학생 이름을 선택해 승인한 학생 Chrome 기기의 로그인을 시작한다. 보호자 화면에 학생 계정을 대신 열거나 학생 비밀번호를 보관하는 방식이 아니다.

## 처음 한 번 설정

1. 보호자 확장의 **학생과 연결 → 새 일회용 연결 코드 만들기**를 누른다. 코드는 10분 안에 한 번 사용할 수 있다.
2. 학생 확장에서 학생 계정을 가입하고 처음 로그인한다. 브라우저 로그인에서는 **내 기기 로그인 유지**가 기본 선택되며 해제할 수 있다.
3. **보호자 연결과 공유 범위**에서 받은 코드를 입력하고 보호자 이름과 공유 범위를 확인한다.
4. 필수 연결 동의와 선택형 **로그아웃 후에도 이 기기에서 보호자가 학생 로그인을 시작하도록 허용**을 선택하고 연결한다. 기기 지원을 선택하지 않아도 기존 강의 배정 연결은 가능하다.

이미 연결한 학생은 같은 영역에서 **로그아웃 후에도 이 기기의 보호자 로그인 지원을 허용**에 동의하고 **연결된 보호자의 이 기기 로그인 지원 허용**을 누르면 된다. 연결 코드를 다시 만들 필요는 없다.

## 다음 로그인

보호자 확장의 **학생 로그인 지원**에서 이름을 선택하고 **선택한 학생 로그인**을 누른다. 요청 대기, 학생 기기에 로그인 정보 전달, 실제 로그인 완료를 따로 표시한다. 다른 학생을 선택하면 이전 학생 상태를 남기지 않는다. 이미 로그인한 학생은 다시 인증하거나 학습 화면 초점을 빼앗지 않는다.

학생 확장 화면이 열려 있으면 5초 간격으로 요청을 확인한다. 화면을 닫아도 확장 백그라운드가 1분 간격의 알람으로 확인하며, 로그인 후 열린 학생 화면이 없으면 전체 수강 탭을 연다. [Chrome 알람 API](https://developer.chrome.com/docs/extensions/reference/api/alarms)의 실행 시점은 지연될 수 있으므로 즉시 또는 정확히 1분 안의 실행을 보장하지 않는다. Chrome 종료·오프라인·절전 상태에서 기기나 브라우저를 원격으로 켜지는 않는다. 요청은 5분 뒤 만료되며 Chrome을 켠 뒤 보호자가 다시 누를 수 있다.

## 중지와 기기 변경

학생은 로그인하지 않은 화면에서도 **이 기기의 보호자 로그인 지원 해제**를 사용할 수 있다. 보호자도 학생을 선택해 **로그인 지원 해제**를 누를 수 있다. 지원 해제는 해당 기기의 원격 로그인 세션도 끝내며 다른 학생 계정을 종료하지 않는다. 오프라인에서 해제를 누르면 기기 내 수신을 먼저 중지하고, 서버 해제를 마치기 위한 재시도를 안내한다.

일반 **로그아웃**은 진행 중인 원격 로그인 요청을 취소하고, 처음 동의한 기기 지원은 유지하므로 보호자가 나중에 새 요청을 보낼 수 있다. **모든 기기 로그아웃**, 비밀번호 복구, 보호자 연결 해제, 승인한 로그인 기기 폐기는 기기 지원까지 취소한다. 이때는 학생이 다시 로그인해 승인해야 한다. 학생 한 명당 승인한 Chrome 프로필 하나만 지원하며 새 기기 승인은 기존 기기의 지원을 대체한다. 기기의 확장을 삭제하거나 Chrome 저장소를 지운 경우에도 첫 승인이 필요하다.

다른 계정이 로그인한 기기는 자동으로 학생 계정을 바꾸지 않는다. 다른 계정의 로그인 유지 정보만 남은 경우에도 덮어쓰지 않는다. 학생 이름 선택만으로 미승인 기기나 임의의 다른 컴퓨터를 로그인시킬 수는 없다.

## 구현과 검사

기기 증명은 학생의 최초 인증과 별도 동의 후 발급하고 서버에는 해시만 저장한다. 학생 확장 ID와 Origin에 묶으며 Chrome 저장소는 신뢰한 확장 문맥만 접근하도록 제한한다. 보호자에게는 요청 상태만 반환하고 학생 접근·갱신 토큰은 승인된 학생 기기에만 전달한다. 증명과 토큰을 URL에 넣지 않는다.

요청 소비와 세션 발급은 SQLite 쓰기 트랜잭션에서 단일 처리한다. 기기 저장 후 완료를 확인하며 늦은 응답은 계정·기기·로그아웃 세대가 일치할 때만 채택한다. 연결 해제와 전체 로그아웃도 같은 쓰기 경계에서 기기 증명을 폐기하므로 폐기 중 등록 경합으로 지원이 되살아나지 않는다. UI와 알람의 동시 확인은 하나로 합친다.

원격 로그인 회귀는 기존 확장 검증 명령에 포함했다.

```bash
PATH="$PWD/.venv/bin:$PATH" \
PYTHONPATH=/tmp/sullivan-video-test \
SULLIVAN_AXE_SOURCE=/tmp/sullivan-extension-a11y/node_modules/axe-core/axe.min.js \
.venv/bin/python scripts/verify_extensions.py \
  --output docs/verification/2026-11-15-remote-login/acceptance-final
```

위 `PYTHONPATH`는 이 개발 환경의 선택형 영상 fixture 도구 경로다. 재현 환경은 프로젝트 의존성, Playwright Chromium, ffmpeg 또는 imageio-ffmpeg, 로컬 axe-core 경로를 준비한다.

- 신규 API 회귀 **37개**: 동의·출처·학생/보호자 소유권·요청 만료·단일 발급·완료 확인·동시 처리·트랜잭션 롤백·모든 폐기 경계·기기 교체·오래된 인증·쓰기 잠금·일반 로그아웃의 진행 요청 취소와 새 요청 허용.
- 신규 백그라운드 회귀 **12개**: 계정 변경·해제·로그아웃 뒤 늦은 응답 폐기, 다른 계정 보존, 잘못된 사용자 세션 거부, 중복 폴링 통합, 연결 오류 복구, Chrome 재시작의 기존 로그인 복원과 원격 로그인 직렬 처리. 기존 인증 회귀에는 갱신 후 원격 기기 식별 보존도 추가.
- 신규 설치 확장 흐름 **8개**: 일회용 연결과 기기 승인, 보호자 Enter 로그인, 학생 화면이 없는 상태의 실제 알람과 새 탭 로그인, 양쪽 해제, 초점 보존, 학생 변경의 지연 응답/오류 차단, 오류 후 재시도.
- [동일 소스 전체 검사 결과](verification/2026-11-15-remote-login/acceptance-final/results.json), [원격 로그인 관찰값](verification/2026-11-15-remote-login/acceptance-final/remote-login/results.json), [접근성 전문 검토](../.a11y-history/2026-11-15-remote-login/report.md), [서버 검토](../.a11y-history/2026-11-15-remote-login/python.json).

최종 결과는 **전체 11개 묶음 통과**, 검사 전후 소스 지문 일치다. API는 **197개 통과·4개 건너뜀**이며 4개는 실제 PostgreSQL 환경이 필요한 기존 검사다. 원격 로그인 흐름의 8개 검사 화면 상태에서 axe 위반 **0건**, 390px·1280px 캡처를 보관했다. 기존 보호자 키보드 배정·학생 초점·문제 모드 차단·원본 영상 미전송 회귀도 통합 검사에 포함한다. 기존 웹의 학생 CSS·역할 포털·앱 소스 diff와 리디자인 레퍼런스 상태 변경은 없다.

실제 Chrome 확장·백그라운드·API·SQLite와 기본 컨트롤을 사용한다. 화면을 닫은 검사는 압축 해제 확장의 알람을 이르게 예약해 실제 알람 이벤트를 발생시킨다. 정상 주기의 지연·절전 복귀 시간, 실제 다른 컴퓨터 사이의 운영 TLS 연결, 사람이 듣는 음질·VoiceOver/NVDA 낭독을 검증했다고 확대하지 않는다. 원본 영상 전송·분석·Gemini 설정과 기존 웹 쿠키 인증·학생 화면은 변경하지 않는다.

## 적용

API 서버를 새 코드로 재시작하고 학생·보호자 확장을 **0.4.8**로 새로고침한 뒤 열린 확장 화면을 다시 연다. 학생 확장에는 백그라운드 확인용 `alarms` 권한을 추가했다. 로컬 패키지는 `dist/extensions/student`, `dist/extensions/guardian`이며 ZIP은 `dist/releases/0.4.8/`에 생성한다. 새 기기 승인 전까지 기존 계정·연결·배정 흐름은 그대로 사용한다. 이 작업은 운영 배포나 스토어 게시를 포함하지 않는다.

이번 생성 패키지의 API 주소는 로컬 개발용 `http://127.0.0.1:8770`이다. 서로 다른 컴퓨터에서 사용하려면 양쪽 확장을 같은 접근 가능한 HTTPS API 서버 출처로 빌드하고 기존 운영 클라이언트 설정을 적용해야 한다. `python scripts/build_extensions.py --server https://실제-서버-주소`와 패키징 스크립트의 동일한 `--server` 옵션을 사용한다. 학생 기기의 localhost는 보호자 컴퓨터의 서버를 가리키지 않는다.
