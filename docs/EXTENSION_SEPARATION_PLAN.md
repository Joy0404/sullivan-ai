# Sullivan AI 학생용·보호자용 확장 프로그램 완전 분리 기획안

작성일: 2026년 11월 12일
상태: 기획 기준선 v1.0 · 구현 현황은 [개발 계획](EXTENSION_DEVELOPMENT_PLAN.md) 참조
대상: 기존 Sullivan AI의 학생·보호자 통합 프로그램
제품 구성: 학생 전용 Chrome 확장 1개 + 보호자 전용 Chrome 확장 1개 + 공통 서버

이 문서는 목표 구조를 정의한다. 아래의 신규 인증·동기화·확장 기능은 아직 구현된 기능을 의미하지 않는다. 이번 작업은 문서 작성에 한정하며 기존 실행 코드·인증·API·배포 설정은 변경하지 않는다.

## 1. 제품 방향과 목표

보호자와 학생은 서로 다른 프로그램을 설치하고, 각자의 화면에서 로그인하며, 상대방의 작업 화면을 거치지 않고 자신의 일을 완료한다. 강의 배정과 학습 상태는 공통 서버를 통해 연결한다.

학생은 보호자의 로그아웃을 기다리지 않고 학습을 시작한다. 보호자는 학생의 학습 세션을 끊지 않고 자료를 준비하고 배정한다. 같은 컴퓨터와 서로 다른 컴퓨터 모두 이 원칙을 따른다.

완전히 분리하는 대상은 설치물, 확장 ID, 로그인 세션, 화면, 탐색 구조, 브라우저 저장소, 요청 권한이다. 공통으로 유지하는 대상은 서버, 데이터 모델, 분석 엔진, 안전 정책, 공통 기능 코드다. 코드 공유는 사용자에게 역할 전환 화면을 제공한다는 의미가 아니다.

## 2. 분리 기준

| 항목 | 학생용 | 보호자용 | 필수 조건 |
| --- | --- | --- | --- |
| 제품명 | Sullivan AI 학생 | Sullivan AI 보호자 | 스토어·아이콘·설치 안내에서 구별 |
| 설치물 | 학생 전용 패키지 | 보호자 전용 패키지 | 별도 확장 ID와 배포 |
| 첫 진입 | 학생 시작·로그인 | 보호자 시작·로그인 | 역할 선택 화면 없음 |
| 로그인 | 학생 계정만 허용 | 보호자 계정만 허용 | 잘못된 역할은 서버에서도 거부 |
| 메뉴 | 수강·질문·복습·개인 설정 | 학생 연결·준비·배정·지원 | 상대 역할 화면 포함 금지 |
| 세션 | 학생 확장 전용 | 보호자 확장 전용 | 공통 로그인 쿠키에 의존하지 않음 |
| 로컬 저장 | 학생 환경·기기별 학습 임시 상태 | 준비 초안·관리 환경 | 상대 확장의 저장소 직접 접근 없음 |
| 데이터 접근 | 자신의 배정 자료·자신의 기록 | 자신과 연결된 학생·자신이 관리하는 자료 | 서버가 매 요청마다 검사 |
| 로그아웃 | 해당 학생 세션 종료 | 해당 보호자 세션 종료 | 상대 역할의 세션 유지 |

학생용 확장에 숨겨진 보호자 페이지를 넣거나, 하나의 설치물에서 역할만 바꾸는 방식은 이 기획의 완료로 인정하지 않는다.

두 확장은 같은 Chrome 프로필에 함께 설치할 수 있다. 다만 확장 분리는 운영체제 계정이나 물리적 기기 접근까지 격리하지 않는다. 서로 다른 사람이 브라우저 자체에 접근할 수 있는 환경에서는 잠금과 별도 Chrome 프로필 사용도 지원 안내에 포함한다.

## 3. 제품별 역할

### 3.1 학생용: 수강과 학습의 중심

핵심 목표는 보호자 조작 없이 배정된 강의를 열고, 접근 가능한 방식으로 학습을 이어가는 것이다.

첫 화면은 ‘이어 듣기’, ‘배정된 강의’, ‘사용법’ 순서로 구성한다. 로그인된 학생에게 보호자 로그인, 자료 분석 관리, 학생 계정 생성 기능을 보여주지 않는다.

| 기능 | 동작 |
| --- | --- |
| 이어 듣기 | 마지막 강의와 저장된 위치 안내 후 학생 조작으로 재생 |
| 강의 목록 | 배정·공개 완료된 강의만 표시 |
| 재생 조작 | 재생, 전체 중지, 구간 이동, 현재 화면 설명 |
| 학습 지원 | 지문 듣기, 원하는 내용 찾기, 근거 기반 질문 |
| 학습 기록 | 자신의 북마크·메모·진도·복습 |
| 개인 설정 | 읽기 속도·음량·음성 안내·단축키·스크린리더 모드 |
| 연결 상태 | 연결된 보호자, 공유 범위, 연결 해제·도움 요청 안내 |

기본 화면은 강의 페이지 옆의 사이드 패널로 제안한다. 긴 지문·학습 기록·파일 재생은 학생 전용 전체 탭으로 확장할 수 있다. 두 화면은 동일 학생 세션을 사용하며 음성 출력 소유권을 하나로 유지한다.

작은 팝업은 실행과 상태 확인에만 사용한다. 팝업을 닫으면 학습이 중단되는 구조로 만들지 않는다.

### 3.2 보호자용: 준비와 배정의 중심

핵심 목표는 학생이 바로 수강할 수 있도록 자료를 준비하고 배정하는 것이다.

첫 화면은 연결된 학생, 준비 중인 자료, 배정 상태를 보여준다. 기본 작업 화면은 보호자 확장에서 여는 전용 전체 탭이다. 자료 업로드·분석·여러 학생 배정은 넓은 화면에서 처리한다.

| 기능 | 동작 |
| --- | --- |
| 학생 연결 | 연결 코드 생성, 연결 요청 확인, 연결 해제 |
| 강의 준비 | 링크·지문·자막·동의한 파일 등록 및 분석 요청 |
| 분석 검토 | 준비 상태, 설명 근거, 보류 항목, 실패·재시도 확인 |
| 강의 배정 | 학생 선택, 순서 지정, 공개·회수 |
| 학습 지원 | 허용된 범위의 진도와 학습 가능 상태 확인 |
| 학습 기본값 | 권장 음성 설정과 문제 보호 정책 설정 |
| 계정 관리 | 자신의 계정·연결 기기·연결 관계 관리 |

‘학생 화면 미리보기’가 필요하면 준비한 자료의 접근성 확인용 미리보기만 제공한다. 실제 학생으로 로그인하거나 학생의 비공개 기록을 여는 기능으로 구현하지 않는다.

## 4. 설치·로그인·계정 연결

### 4.1 최초 사용 흐름

1. 보호자가 보호자용 확장을 설치하고 계정을 만든다.
2. 보호자가 학생 연결 요청을 생성한다. 서버는 일회용·유효기간 있는 코드를 발급한다.
3. 학생은 학생용 확장을 설치하고 학생 계정을 생성하거나 기존 계정으로 로그인한다.
4. 학생이 코드를 입력하면 연결할 보호자와 공유 범위를 음성·텍스트로 확인한다.
5. 학생 확인 후 연결을 완료한다. 보호자는 연결 완료를 확인하고 강의를 배정한다.
6. 학생용 확장에 배정된 강의가 나타난다. 학생이 선택하면 수강을 시작한다.

코드는 계정 연결 요청을 식별하는 용도다. 코드만으로 로그인하거나 계정을 탈취할 수 없도록 한다. 만료·재사용·입력 시도 제한을 적용하며 계정 비밀번호를 서로 전달하지 않는다.

학생이 최초 설정을 혼자 하기 어려운 경우에는 안내가 있는 기기 설정 보조 절차를 제공한다. 보조가 끝나면 학생 세션만 남기고 보호자 인증 정보는 학생 확장에 저장하지 않는다. 연령에 따른 동의·대리 설정 정책은 공개 서비스 출시 전에 별도 확정한다.

### 4.2 일상 사용 흐름

보호자: 보호자 확장 열기 → 자료 준비 → 분석 결과 확인 → 학생 배정 → 상태 확인.

학생: 학생 확장 열기 → 이어 듣기 또는 강의 선택 → 학습 → 진행 위치 저장.

어느 흐름에도 상대방 로그아웃이나 역할 전환을 넣지 않는다.

### 4.3 인증 설계 방향

- 두 확장은 별도 클라이언트로 등록하고 별도 인증 세션을 발급한다.
- 1차 권장안은 서버 로그인 페이지를 여는 표준 인증 흐름과 Authorization Code + PKCE다. 학생·보호자 진입 주소는 분리한다.
- 로그인 완료 시 확장 클라이언트와 계정 역할을 함께 검사한다. 확장 ID나 클라이언트 ID 자체를 사용자 권한의 근거로 삼지 않는다.
- 수명이 짧은 접근 자격과 회전·폐기 가능한 갱신 자격을 사용한다. 실제 보관 위치와 복구 방식은 인증 기술 검증에서 확정한다.
- 자격 증명은 콘텐츠 스크립트나 강의 사이트에 전달하지 않는다. 콘텐츠 스크립트는 제한된 명령만 확장 내부에 요청한다.
- 개별 로그아웃, 해당 역할의 모든 기기 로그아웃, 계정 잠금을 구분한다.
- 같은 서버의 기존 공통 쿠키를 그대로 사용하는 방식은 채택하지 않는다.

## 5. 데이터 소유권과 공유 범위

‘서버 하나’는 운영·동기화의 중심이 하나라는 뜻이다. 모든 사용자에게 모든 데이터를 열거나, 모든 데이터를 하나의 테이블·프로세스에 넣는다는 뜻은 아니다.

| 데이터 | 기준 소유자 | 학생 접근 | 보호자 접근 |
| --- | --- | --- | --- |
| 계정·인증 | 각 사용자 | 본인 | 본인 |
| 연결 관계 | 연결 당사자 | 본인 관계 확인 | 본인 관계 확인 |
| 강의 준비 초안 | 준비한 보호자 | 공개 전 접근 불가 | 본인 자료 관리 |
| 공개된 분석·지문 | 강의 자료 | 현재 배정 범위 | 본인 관리 자료 |
| 배정·순서 | 보호자 관리 | 자신의 배정 조회 | 연결 학생에게 배정·회수 |
| 진도·마지막 위치 | 학생 | 조회·갱신 | 연결·공유 범위 안에서 요약 조회 |
| 메모·질문 원문·검색 | 학생 | 본인 조회·관리 | 기본 비공개 |
| 학생 음성·화면 원본 | 해당 학생의 원본 | 허용한 처리 범위 | 자동 열람 불가 |
| 읽기 속도·음량 | 학생 | 직접 변경 | 권장 기본값 제안 |
| 문제 보호 정책 | 서버에서 적용 | 허용 범위 내 강화 | 허용 범위 내 설정 |

메모·질문 원문을 보호자에게 기본 비공개로 두는 것은 본 기획의 제안이다. 현재 제품의 모든 공유 정책이 이미 이와 같다는 뜻은 아니다. 학생이 항목을 선택해 공유하는 기능은 후속 범위로 둔다.

연결 해제 시 보호자는 이후 학생 기록을 조회할 수 없다. 학생 개인 기록은 즉시 삭제하지 않는다. 회수된 강의의 재생 권한과 개인 메모 보존을 구분하고, 강의 본문을 포함한 캐시는 접근 종료 시 정리한다. 기존에 외부로 내보낸 자료의 회수까지 보장하지 않는다.

## 6. 공통 서버와 프로그램 구조

### 6.1 구성

```text
보호자 전용 확장 ── 보호자 인증·API ──┐
                                    ├─ 공통 서버 ─ 계정·연결·배정·학습 DB
학생 전용 확장   ── 학생 인증·API ───┘           └ 분석 작업·공통 안전 엔진
       │
       └ 지원 강의 탭의 재생 상태·허용된 조작
```

서버는 역할과 데이터 관계를 기준으로 접근을 검사한다. 학생은 다른 학생 ID나 보호자 ID를 요청에 넣어도 권한을 얻지 못한다. 보호자는 연결되지 않은 학생과 다른 보호자의 자료에 접근할 수 없다.

### 6.2 서버 책임

- 계정·클라이언트별 인증과 연결 관계 관리.
- 강의 준비·분석 작업의 영속 저장 및 실패 복구.
- 강의 버전·배정·공개 상태와 진행 기록 저장.
- Gemini 등 공급자 호출과 API 키 보관.
- 저확신도 보류·정답 차단·근거 추적 정책의 최종 적용.
- 인증 폐기·연결 해제·배정 회수와 필요한 감사 기록.

긴 분석은 서버 작업으로 처리한다. 보호자 확장을 닫아도 승인된 분석 작업은 계속되며, 다시 열면 서버에서 상태를 복원한다. 모델 변경이나 공급자 교체는 이번 분리의 필수 범위로 넣지 않는다.

### 6.3 확장 책임

학생 확장은 학습 화면, 재생 제어, 접근 가능한 안내, 학생 조작, 로컬 임시 상태를 맡는다. 보호자 확장은 준비 화면, 업로드 동의, 배정과 관리 조작을 맡는다.

서비스 워커는 메시지 중계·인증 요청·이벤트 처리를 맡긴다. 장시간 실행이나 메모리 상태의 영구 유지를 전제로 하지 않는다. 재생·음성은 적절한 화면 또는 검증된 미디어 문맥에서 처리하고, 화면 종료·재시작 시 중복 음성과 잘못된 자동 재생을 방지한다.

### 6.4 코드 관리 제안

같은 GitHub 저장소에서 별도 패키지를 빌드한다. 기존 공통 엔진을 복제해 두 벌로 유지하지 않는다.

```text
apps/
  api/                   공통 서버와 기존 분석 코어
  student-extension/     학생 전용 진입점·화면·manifest
  guardian-extension/    보호자 전용 진입점·화면·manifest
  web/                   전환 완료까지 유지할 기존 웹
packages/
  contracts/             요청·응답·이벤트 형식
  learning-core/         재생 상태·명령·학습 기능의 공통 코드
  accessibility/         공통 초점·안내·설정 기능
```

위 경로는 향후 구현을 위한 제안이다. 현재 폴더를 이동하거나 생성했다는 뜻은 아니다. 공통 패키지에서 상대 역할의 화면이 학생 배포물에 따라 들어가지 않도록 빌드 결과를 확인한다.

## 7. 강의·영상 전달 방식

### 7.1 링크 강의

보호자는 강의 링크와 허용된 보조자료를 준비한다. 서버는 링크 식별 정보·분석 결과·배정을 저장한다. 학생은 원본 사이트에서 본인에게 허용된 방식으로 강의를 연다.

보호자 로그인이나 유료 수강 권한을 학생에게 전달하지 않는다. 영상 재생 권한과 Sullivan의 분석·배정 권한은 별개다.

### 7.2 로컬 파일 강의

현재 브라우저 저장소에 있는 원본 영상은 다른 확장이나 다른 기기에 자동 공유되지 않는다. 이 제약을 숨기지 않는다.

1차 버전은 보호자가 분석·배정한 자료와 학생이 직접 선택한 원본 파일을 연결하는 방식으로 제안한다. 원본은 서버에 상시 보관하지 않는다. 파일 이름만으로 동일 강의라고 판정하지 않고 길이·크기 등 식별 정보와 확인 절차를 사용한다. 연결을 확인하지 못하면 시간대별 자동 해설을 시작하지 않는다.

이는 보호자에서 학생으로 영상을 자동 전송하는 기능이 아니다. 학생 기기에 파일을 전달하고 선택하는 과정의 접근성은 별도 검증 항목이다. 기기 간 원본 전달이 필수라면 후속 단계에서 명시적 동의·암호화·보존 기간을 갖춘 전송 기능을 별도 기획한다.

기존 웹의 암호화 영상 저장소는 새 확장에서 바로 읽을 수 없다. 필요 시 기존 웹에서 사용자가 승인하는 내보내기·재선택 절차를 제공하고, 자동 이전으로 표현하지 않는다.

### 7.3 분석과 현재 화면 설명

이미 준비된 분석을 재생 시점에 맞춰 안내하는 기능과, 실제 현재 탭 화면을 새로 분석하는 기능을 구별한다. 준비된 자료만 있는 경우에는 ‘현재 시점에 준비된 설명’이라고 안내한다.

실제 화면·오디오 캡처는 별도 기술 검증과 사용자 시작·전송 동의가 필요한 후속 범위다. 샘플이나 사전 분석 결과를 실시간 화면 분석이라고 표시하지 않는다.

## 8. 강의 사이트 연결과 확장 권한

처음부터 모든 인터넷 강의 사이트를 지원한다고 약속하지 않는다. 첫 버전 후보는 공개 YouTube 강의 탭, 자체 학생 파일 재생 화면, 지문 자료다. 실제 지원 확정은 플레이어 제어·시간 동기화·접근성 검증 후에 한다.

사이트 연결은 공통 명령과 사이트별 어댑터로 분리한다. 공통 명령은 재생·중지·현재 위치·탐색·재생 가능 상태로 제한한다. 지원하지 않는 플레이어에서는 가능한 기능만 안내하고 재생 제어를 성공으로 표시하지 않는다.

- 학생용: 사이드 패널·저장 권한을 기본 후보로 하고, 탭 연결은 사용자 실행 및 필요한 사이트 권한에 한정한다.
- 보호자용: 서버 통신·저장 중심으로 시작한다. 현재 페이지 링크 가져오기는 사용자가 요청할 때만 동작하게 한다.
- 사이트 접근을 지속해야 하는 경우에는 해당 사이트에 대한 선택 권한을 별도 요청한다. 일시적인 `activeTab` 권한이 모든 이동·프레임 접근을 보장한다고 가정하지 않는다.
- 전체 사이트 접근·상시 캡처·마이크 권한을 두 확장에 일괄 부여하지 않는다.
- 콘텐츠 스크립트가 서버 URL이나 임의 API를 자유롭게 호출하는 중계 통로가 되지 않도록 메시지 종류·발신 탭·입력을 검사한다.
- DRM 우회·보호된 스트림 다운로드·유료 강의 무단 수집은 기능 범위에 넣지 않는다.

## 9. 학생 접근성과 음성 동작

학생용 확장은 음성·키보드·스크린리더 중 하나만 사용할 수 있는 상황에서도 핵심 학습을 완료할 수 있어야 한다.

- 첫 초점, 현재 위치, 로딩·저장·실패 상태를 접근 가능한 이름과 안내로 전달한다.
- 앱 음성과 스크린리더 음성이 겹치지 않도록 모드를 구분한다.
- 학생 패널·전체 탭·강의 사이트 사이를 이동하고 돌아오는 단축키와 안내를 제공한다.
- 기존 Space 길게·두 번·세 번 명령은 학생 화면에서 보존 가능성을 검증한다. 강의 사이트 전체에서 무조건 키를 가로채지 않는다.
- 외부 페이지의 입력칸, 기본 재생 키, 스크린리더 키와 충돌하면 원래 입력을 우선한다. 단축키 변경과 명시적 학습 모드를 제공한다.
- 마이크 거부·인식 실패 시 동일 기능의 타자 명령을 제공한다.
- 화면 전환과 네트워크 지연 후에도 오래된 음성이 시작되거나 학생이 중지한 강의가 다시 재생되지 않게 한다.
- 확장 설치·로그인·기기 연결·파일 선택·권한 요청부터 실제 VoiceOver와 NVDA로 검증한다.

현재 Mac 로컬 실행기의 시스템 음성 기능은 확장 설치만으로 제공되지 않는다. 확장에서는 브라우저의 실제 음성·마이크 허용 동작을 다시 검증하고, 자동 첫 안내가 항상 가능하다고 약속하지 않는다.

초기 동기화는 화면 진입·포커스 복귀·수동 갱신·주기적 조회로 시작한다. 이후 필요에 따라 실시간 알림을 추가한다. 서비스 워커의 상시 연결에 의존하지 않는다.

## 11. 기존 프로그램에서의 전환

현재 코드 확인 결과를 기준으로 한 주요 전환 대상은 다음과 같다.

| 현재 구성 | 전환 계획 |
| --- | --- |
| `apps/web/role-portal.js`의 역할별 화면·공통 상태 | 역할별 진입점과 상태로 분리, 공통 학습 기능 추출 |
| `apps/api/app/local_access.py`의 공통 쿠키 | 확장별 독립 인증 도입, 역할·관계 권한 유지·보강 |
| 로컬 SQLite 계정·배정·진도 | 운영 서버 저장으로 명시적 이전, ID 대응·건수 검증·복구 절차 준비 |
| 프로세스에 의존하는 분석 세션 | 서버 작업과 분석 패키지의 영속 저장 |

| 외부 YouTube API 스크립트 로딩 | 확장 정책에 맞는 원본 탭 제어 또는 별도 재생 경계 검증 |
| 로컬 Mac 로그인 시스템 음성 | 브라우저 기반 시작 안내로 재설계·실기 검증 |
| 기존 분석·문제 보호 코어 | 공통 서버 기능으로 재사용, 출력 경로 회귀 검증 |

기존 로컬 서비스는 새 학생·보호자 흐름의 검증이 끝날 때까지 유지한다. 데이터 이전은 복사·검증·전환 순서로 진행하며 원본 DB를 먼저 삭제하지 않는다. 비밀번호 해시 호환성을 확인하고 필요하면 안전한 계정 재설정을 사용한다.

실제 구현 전 저장소 지침도 새 구조에 맞게 정비한다. 현재 `AGENTS.md`의 인증·API 변경 제한은 기존 리스킨 작업의 보호 조건이므로, 신규 인증·API 구현 범위를 명시한 뒤 전환 작업을 진행한다.

## 12. 단계별 개발 범위와 통과 조건

### 단계 0: 기술 검증과 결정 확정

검증 대상은 동일 Chrome 프로필의 독립 로그인, 공개 YouTube 탭 제어, 학생 패널 초점 이동, 한국어 음성·마이크, 확장 정책, 파일 선택과 시간 동기화다.

통과 조건: 가능한 기능·불가능한 기능을 실제 Chrome에서 확인하고 첫 지원 대상과 권한 목록을 확정한다. 미검증 기능은 출시 약속에서 제외한다.

### 단계 1: 서버·인증·연결 기반

확장별 인증, 학생·보호자 계정, 연결 코드, 서버 권한 검사, 영속 분석·배정 저장을 구축한다.

통과 조건: 같은 프로필에서 동시 로그인 가능, 상대 역할 API 접근 차단, 연결되지 않은 계정 접근 차단, 개별 로그아웃 독립성 확인.

### 단계 2: 보호자 준비·학생 수강의 첫 완결 흐름

보호자 확장에서 샘플·지문·지원 링크를 준비·배정하고, 학생 확장에서 목록·재생·지문·진도 저장을 제공한다. 샘플과 실제 분석 상태를 명확히 구분한다.

통과 조건: 서로 다른 기기에서 준비 → 배정 → 수강 → 진행 확인까지 완료. 상대 역할 화면이나 계정 전환을 사용하지 않음.

### 단계 3: 기존 학습 기능 이전

검증된 실제 분석, 안전한 자동 해설, 검색·질문·복습·메모, 음성 명령과 개인 설정을 이전한다. 로컬 원본 파일 연결을 검증한다.

통과 조건: 기존 핵심 기능의 대응표 완성, 저확신도·정답 차단·중지·이어 듣기 회귀 검증, 실제 스크린리더·음성 사용 확인.

### 단계 4: 이전·장애 복구·배포

기존 계정·배정·진도 이전, 확장 버전 차이, 네트워크 단절, 권한 회수, 두 스토어 등록과 개인정보 안내를 준비한다.

통과 조건: 데이터 검증과 복구 연습 완료, 두 설치물의 권한·포함 코드 확인, 실제 사용자 흐름 검증 후 출시.

날짜와 개발 기간은 단계 0의 기술 검증과 대상 기능 확정 후 산정한다. 미확인 사이트 호환성을 전제로 일정을 고정하지 않는다.

## 13. 첫 버전의 경계

첫 버전에 포함할 대상은 두 확장의 독립 설치·인증, 보호자와 학생의 연결, 준비·배정·수강, 서버 기반 기록, 지원 강의의 재생 연결, 핵심 접근성과 기존 안전 정책이다.

첫 버전에서 별도 검증·후속 기획으로 남기는 대상은 모든 강의 사이트 지원, 상시 화면·오디오 분석, 원본 영상의 기기 간 자동 전송, 완전 오프라인 수강, 다수 보호자의 공동 관리, 학생 원격 조작이다.

데이터 모델은 연결 관계를 별도 관리하여 후속 확장을 열어두되, 초기 화면과 권한은 학생당 주 보호자 한 명을 기준으로 단순화한다. 연결 교체 시 이전 보호자의 권한을 종료하는 절차를 제공한다.

## 14. 최종 인수 기준

- [ ] 학생·보호자 확장이 별도 ID·패키지·스토어 항목으로 설치된다.
- [ ] 두 프로그램 어디에도 역할 선택·역할 전환을 요구하지 않는다.
- [ ] 같은 컴퓨터에서 동시에 로그인하고 각각 독립적으로 로그아웃할 수 있다.
- [ ] 학생 배포물에 보호자 화면과 관리 기능이 포함되지 않는다.
- [ ] 서버가 역할·연결 관계·배정·자료 소유권을 모두 검사한다.
- [ ] 보호자는 다른 학생·보호자의 데이터를 읽을 수 없다.
- [ ] 서로 다른 컴퓨터에서 배정과 진행 기록이 연결된다.
- [ ] 보호자가 없어도 학생이 수강·중지·이어 듣기를 완료한다.
- [ ] 자료 준비 화면을 닫아도 서버 분석 상태를 복원한다.
- [ ] 네트워크 단절·분석 실패·만료 인증·회수된 배정에서 이해 가능한 복구 안내를 제공한다.
- [ ] 실제 VoiceOver·NVDA에서 설치 후 로그인부터 복습까지 검증한다.
- [ ] 저확신도 정보와 보호 대상 정답이 UI·질문·요약·음성으로 노출되지 않는다.
- [ ] 원본 영상·학생 음성·화면을 기본값으로 서버에 상시 저장하지 않는다.
- [ ] 기존 데이터 이전의 건수·소유권·진도와 복구 가능성을 검증한다.
- [ ] 두 확장과 서버의 버전 차이에서도 지원 범위의 흐름이 동작한다.
