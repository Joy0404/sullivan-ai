# 2026-11-15 반복 검사·수정 결과 — 0.4.6

수정 전 실패를 재현하고, 수정 후 검사를 통과시킨 뒤 더 늦은 응답·입력 순서로 경계를 넓혀 다시 검사했다. 이번에 확인한 실패 경로는 수정했다. 모든 실서비스·기기에 문제가 전혀 없다고 선언한 것은 아니다.

## 1차 검사 → 수정

인증 시험에서 다음 3개 실패를 재현했다. 실제 사용자 계정이나 토큰을 사용하지 않은 격리된 JS 실행 환경이다.

- 갱신 응답이 늦게 도착하면 로그아웃한 세션을 되살릴 수 있었다.
- 이전 계정의 갱신 실패가 현재 다른 계정의 세션까지 지울 수 있었다.
- 이전 계정의 401 저장 요청을 새 계정의 토큰으로 재전송할 수 있었다.

세션 쓰기를 확장 간 공유 잠금으로 직렬화했다. 갱신 결과를 저장하기 전에 세대·원래 갱신 자격을 다시 확인하고, 삭제도 대상 자격과 현재 세션이 같을 때 실행한다. 로그인 계열마다 브라우저 전용 `auth_epoch`를 저장하며 일반 토큰 갱신에서는 유지한다. API 형식·쿠키 인증을 변경한 것이 아니다.

실제 설치한 두 확장·임시 API/DB·디코딩 MP4에서 다음 4개 실패도 재현했다.

| 재현한 실패 | 수정과 관찰 |
| --- | --- |
| 위치 저장이 두 번 실행됨 | 구간 이동이 수행한 저장 뒤에 중복 PUT을 보내지 않는다. 요청 수 **2회 → 1회**. |
| 3초 저장 응답 대기 중 입력한 5초까지 자동 저장됨 | 제출한 3초만 저장하고 새 5초 입력은 유지한다. 현재 영상은 3초에 있는데 기록만 5초로 바뀌는 불일치를 막는다. 새 입력은 저장 대기라고 안내한다. |
| 보호자 편집 저장 응답이 새 입력·초점을 지움 | 응답 때 폼을 재생성하지 않는다. 제목·체크 상자·초점을 보존하고 저장된 모델만 갱신한다. |
| 이전 강의 회수 응답이 다른 강의 편집 화면을 다시 그림 | 회수 대상과 입력·초점 세대를 고정한다. 다른 편집 화면은 그대로 둔다. |

[인증 수정 전 로그](verification/2026-11-15-races/before/client.log), [브라우저 수정 전 결과](verification/2026-11-15-races/before/browser/results.json), [1차 수정 후 결과](verification/2026-11-15-races/round1/results.json)를 보존했다.

## 2차 경계 검사 → 추가 보완

저장소 변경 알림 자체를 늦춰 보니 알림에만 의존한 방어로는 새 계정 토큰 재사용과 이전 계정 응답 전달을 막지 못했다. [중간 실패 로그](verification/2026-11-15-races/before/client-delayed-events.log).

요청 시작 화면이 알고 있던 계정과 실제 세션을 비교하고, 전송·401 재시도·응답 반환 시점에도 저장소의 계정·로그인 계열을 확인하도록 보완했다. 알림이 늦어도 다른 계정 자격을 빌리지 않는다. 동시 만료 요청이 한 번만 갱신하는 기존 동작도 유지한다.

최종 인증 경계 **7개**를 기본 JS 검사에 추가했다. 브라우저 경합 검사는 새 체크 상자 선택 보존까지 강화했고, 오래된 목록 응답이 완료 작업을 다시 진행 중으로 되돌리지 않는 경계를 더해 **5개**가 됐다. 학생·보호자 목록 모두 최신 조회만 반영한다.

신규 인증 테스트의 HTTP·저장소는 시험 장치다. 브라우저 경합은 실제 확장/API/DB/영상에서 응답 순서만 제어했다. 실제 사용자 DB와 유료 공급자는 사용하지 않았다. 통합 명령·CI에 신규 검사를 추가했으므로 다음 실행에서도 함께 검사한다.

## 실환경 확인 범위 확장

자동 통합 검사와 별개로 공개 YouTube 샘플 페이지에서 실제 영상 제어 함수를 실행했다. 재생 위치가 약 0초에서 3초까지 증가했고, 10초 이동과 정지가 동작했다. [관찰값](verification/2026-11-15-races/live-video-playback-probe.json). 로그인·스트림 다운로드·보호된 영상 우회·유료 분석은 하지 않았다. 이 검사는 페이지의 제어 함수 확인이며, 사이드 패널 권한·worker까지 포함한 전체 사이트 인증은 아니다.

현재 로컬 Chromium에서는 합성 시험 영상 WebM·MOV·M4V도 `StudentMedia`를 통해 실제 디코딩·재생·이동·정지했다. [코덱 결과](verification/2026-11-15-races/codec-probe.json). 재생권 메시지는 시험 장치이며 원본 식별 없는 수동 재생 경로다. 다른 OS·코덱·브라우저의 보증으로 확대하지 않는다. 최초 codec 진단의 보안 컨텍스트 설정 오류는 제품 실패로 세지 않았고 [초기 기록](verification/2026-11-15-races/codec-probe-environment-first.json)을 남겼다.

이 문서 이후 사용자는 Chrome, 임의 강의 링크·파일, 기존 단축키와 자연 음성 자동 선택으로 기준을 정했다. 사이트·OS·스크린리더 정보 응답을 진행 조건으로 삼지 않는다. [0.4.7 연결 확대](EXTENSION_CHROME_PLAYBACK.md)를 따른다. 실제 Gemini 품질·마이크 서비스·보조기기 전체 사용은 자동 검사와 구분한다.

## 적용

이 문서의 수정 버전은 **0.4.6**이며 최신 로컬 패키지는 [0.4.7 안내](EXTENSION_CHROME_PLAYBACK.md)를 따른다. 학습 기록 저장 완료를 확인한 뒤 두 확장을 새로고침하고 기존 확장 탭·학생 패널을 다시 연다. 운영 배포·스토어 게시·사용자 데이터 삭제는 하지 않았다.

재현 명령:

```bash
PATH="$PWD/.venv/bin:$PATH" \
PYTHONPATH=/tmp/sullivan-video-test \
SULLIVAN_AXE_SOURCE=/tmp/sullivan-extension-a11y/node_modules/axe-core/axe.min.js \
.venv/bin/python scripts/verify_extensions.py --output docs/verification/extension-acceptance
```

환경별 ffmpeg·axe 경로는 바꿔 지정한다. 외부 진단은 네트워크 영향을 받으므로 CI의 로컬 통과 조건과 분리해 기록한다.
