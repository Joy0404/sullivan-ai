## 개인 필기와 데이터 보존

- 제목·태그 입력 없이 강의별 여러 항목을 작성·수정·삭제한다. 첫 문장을 목록 제목으로 사용하고 시작 시점을 기록한다.
- 원문을 직접 선택한 경우에만 안전한 문장·식에 연결한다. 선택하지 않으면 자유 필기다. AI가 연결 대상을 고르지 않는다.
- 원문은 별도 읽기 전용 텍스트로 확인하고 닫기/실제 Esc 뒤 원래 필기 선택 범위·커서로 돌아온다. 학생 작성 본문은 native textarea이며 자동 교정·요약·재작성하지 않는다.
- 900ms 입력 대기 뒤 자동 저장한다. 한글 composition 중 저장을 미루고, 일반 Space·방향키·실행 취소를 가로채지 않는다. 자동 저장과 목록 갱신은 편집 초점을 이동하지 않는다.
- 네트워크 요청 전에 학생 계정·강의별 초안을 `chrome.storage.local`에 보존한다. 원문 텍스트는 초안에 넣지 않는다. 실패 뒤 화면을 다시 열어 초안을 복원하고 재시도한다. 기기 보존도 실패하면 화면을 유지하라는 오류를 구분한다.
- 저장 대기는 최초 변경 때만 안내하고 본문을 반복 낭독하지 않는다. 결과 수는 지연해 짧게 알린다. 다른 작업에 있을 때 저장이 실패하면 전역 오류로도 알린다. 스크린리더 모드에서는 앱 TTS가 중복해서 읽지 않는다.
- revision으로 동시 수정을 검사한다. 충돌은 덮어쓰지 않고 초안을 유지한다. 명시적 ‘새 필기로 보존’은 새 기기 초안을 먼저 만든 뒤 이전의 충돌 초안만 정리하며 다른 화면의 서버 기록을 지우지 않는다.
- 텍스트와 Markdown으로 내보낸다. 내보내기 전 미저장 초안을 확인하고 연결 원문을 다시 검사한다.
- 기존 `progress`의 메모·위치·북마크·밑줄은 별도 계약 그대로 유지한다. 기존 한 칸 메모는 학생의 복사 버튼으로 새 필기를 만들며 원본을 삭제하지 않는다.
- 별도 `student_notes` 테이블은 배정·원본 삭제와 분리되어 있다. 설정의 보관된 내 필기에서 배정 종료 뒤에도 자기 본문을 다시 열어 수정·내보낸다. 이때 연결 원문·현재 다른 강의의 기존 메모는 노출하지 않는다.
- 보호자 요약에 새 필기 본문을 추가하지 않는다. 전체 필기를 AI 공급자에게 보내지 않는다. 기기 초안은 같은 Chrome 프로필에 남으므로 개인 기기에서 사용하며, 다른 학생 계정의 UI에서는 조회하지 않는다.

새 음성 필기 명령, 수학 편집기·필기 인식·AI 재작성·협업·강의 녹음은 추가하지 않았다.

## API와 안전 경계

새 경로는 `/extension/v1/student/notebooks`, `/lectures/{id}/notes`, `/notes/{note_id}`, `/notes/{note_id}/source`, `/notes-export`, `/note-sources`이다. 모두 확장 학생 인증을 요구한다. 기존 웹 쿠키나 보호자 자격으로 대체하지 않는다.

연결에는 원문 식별자와 SHA-256 해시 지문만 보관한다. 원문 옵션은 현재 정제된 학생 자료에서 만든다. 조회·내보내기 때 현재 권한과 공개 상태, confidence 0.72, HOLD/SKIP, 문제 모드 answer 차단을 다시 적용한다. 원문이 변경되어 해시가 다르거나 접근이 철회되면 원문을 반환하지 않는다. 학생이 직접 작성한 자기 풀이 본문에는 이 원문 필터를 적용해 삭제하지 않는다.

기존 학습 자료 내보내기도 서버의 현재 학생 자료를 다시 받아 안전 상태를 재검사한다. 낮은 확신도·문제 정답은 새 원문 옵션·필기 참조 텍스트·검색·기기 초안·내보내기에 유입되지 않는다. 새 원문 수정 이력 저장 기능은 만들지 않아 후보 텍스트의 사본을 남기지 않는다.

학생 영상 연결·보관·동의 모듈은 변경하지 않았다. 실제 학생 요청을 관찰해 JSON 외 원본 업로드 요청이 없음을 검사했다. 공개 MP4는 브라우저에서 디코딩·재생했으며 새 영상 분석 결과로 표현하지 않았다. 실제 분석·질문 공급자는 기존 설정·동의·실패 처리 경계를 그대로 사용한다.

## 수정 전후 Tab과 접근 경로

백업 코드와 현재 코드를 각각 설치한 Chromium에서 **동일한 과학 샘플 snapshot SHA-256**을 확인하고 비교했다. 자료는 4문단·7문장이다.

| 조건 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 기본 접힘 상태 정방향 Tab | 11번째 키에서 영상 details summary에 멈춤 | 닫힌 내부 입력을 건너뛰며 정·역방향 통과 |
| 기존 안내 경로 이용 | 학습 기록 링크 경유 메모까지 10회 키 입력 | 듣기 제목에서 Shift+Tab 6회 → Enter → Tab → Enter, 새 필기 편집란까지 9회 |
| 모든 details를 펼쳐 순서대로 이동 | 메모까지 Tab 74회 | 다른 작업의 자료·검색·설정은 듣기 순환에서 제외 |
| 본문 문장 버튼 | 7개 | 0개, 선택 제어와 공통 조작으로 대체 |

74회는 기존 전체 순회 조건이고, 10회는 기존 링크를 이용한 경로다. 기존에도 건너뛰기 경로가 있었음을 구분한다. 새 필기와 기존 한 칸 메모는 서로 다른 편집 기능이다.

원인은 Chromium에서 닫힌 details의 파일 입력도 `getClientRects().length == 1`을 반환하는 것이었다. 모든 닫힌 조상 details를 검사해 첫 summary 안의 보이는 내용만 후보로 삼는다. 초점 이동 실패 시 각 후보를 한 번만 검사한다. 중첩·열기/닫기·역방향·무효 후보와 실제 Chrome 사이드 패널의 Tab을 회귀 검사했다.

## 적용과 남은 실사용 검증

로컬 `dist/extensions/student`와 `guardian`을 다시 빌드했고 생성된 학생 JS가 소스와 일치함을 확인했다. 새 필기 API를 제공하는 현재 서버 코드와 확장을 함께 사용해야 한다. 이미 실행 중인 서버는 무단 종료·재시작하지 않았다. 사용하는 서버에 현재 코드를 적용한 뒤 Chrome의 확장 다시 로드와 열린 패널 다시 열기가 필요하다.

실제 시각장애 학생 평가, VoiceOver/NVDA 실기, 실제 한국어 IME의 OS 후보창, 사람이 듣는 TTS 품질·실제 마이크 서비스, 유료 분석, 외부 강의 사이트·DRM 플레이어 호환성은 미검증이다. 한글은 브라우저 composition 이벤트와 실제 텍스트 삽입 경로, 음성은 명시적 모의 서비스 경계로 시험했다. 자동 접근성 결과나 생성된 시연 영상을 이 실사용 검증으로 대체하지 않는다.
