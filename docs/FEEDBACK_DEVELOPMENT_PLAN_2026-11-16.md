# Sullivan AI 체험 피드백 기반 개발 기획안

작성일: 2026-11-16 · 버전: 1.1, 추가 피드백 통합 · 상태: 개발 제안, 기능 구현 전

후속 적정성 검토와 개발 범위·우선순위·토큰/효율·검증 기준을 조정한 [개발 기획안 v2.2](FEEDBACK_DEVELOPMENT_PLAN_V2_2026-11-16.md)을 현재 착수 기준으로 사용한다. 이 문서는 이전 요구사항과 전체 피드백 정리로 보존한다.

기획 근거는 제공된 학생·보호자 체험 피드백과 현재 저장소의 구현이다. 구현 기준은 최근 검증한 `final` 브랜치의 `6b01f75`다. 이 문서 작성으로 제품 코드·인증·API·모델 설정을 변경하지 않았다.

## 1. 개발 목표

**학생이 처음 사용할 때 조작을 익히고, 필요한 화면 정보를 확인하며, 문제가 생겨도 스스로 수강을 이어갈 수 있도록 한다.** 보호자는 처음 연결과 강의 준비를 지원하고, 학생은 일상적인 수강을 주도한다.

유지할 제품 가치는 다음 세 가지다.

- 학생·보호자의 역할 분리와 보호자가 곁에 없어도 가능한 수강.
- 강사가 말하지 않은 중요한 화면 정보의 접근성과 긴 지문 원문 읽기.
- Space 중심 조작과 타자 대체, 필요한 순간에 제공하는 해설.

**이번 피드백의 최우선 개발 과제는 학생·보호자 각각의 튜토리얼이다.** 처음 시작하기와 두 프로그램 연결하기를 직접 연습하고, 익숙해진 뒤에도 필요한 명령과 사용법을 바로 찾아 들을 수 있게 한다. 음성 명령이 어떻게 인식되고 어떤 동작으로 실행됐는지, 현재 어느 프로그램에서 무엇을 처리하는지도 확인할 수 있게 한다.

설명량 조절과 독립 수강을 함께 보완한다. 학생의 필기를 대신 작성하거나 문제의 답을 대신 제공하는 기능은 이번 범위에 넣지 않는다.

| 개발 순서 | 핵심 산출물 |
| --- | --- |
| 1. 사용법 익히기 | 학생 조작 연습, 보호자 가입·연결·배정 튜토리얼 |
| 2. 조작 결과 확인하기 | 음성 인식·실행 피드백, 현재 상태와 최근 명령 확인 |
| 3. 필요할 때 도움받기 | 단계별 음성 안내서, 상황별 명령 목록, 도움말·상태 확인 단축키 |
| 4. 학습 흐름 다듬기 | 설명량 선택, 부분 재청취, 보호자 도움 없이 다음 수강 시작 |

## 2. 피드백 해석과 근거의 범위

| 피드백에서 확인한 의견 | 개발 가설 | 우선 대응 |
| --- | --- | --- |
| 역할이 분리돼 명확하고, 보호자가 계속 옆에 있지 않아도 된다는 장점 | 역할 분리는 유지하되 두 프로그램의 연결 관계를 처음에 설명해야 한다. | 역할별 시작 안내와 연결 단계 표시 |
| 가입·학생 연결이 복잡하고 누군가의 설명이 필요함 | 설명서의 존재와 실제 첫 과업의 성공 사이에 간격이 있다. | 현재 단계와 다음 행동이 보이는 연결 가이드 |
| 안내가 필요하다는 의견이 추가 응답에서도 반복됨 | 학생·보호자 튜토리얼을 다음 버전의 중심 과제로 우선 개발해야 한다. | 역할별 시작 튜토리얼과 상시 재진입 |
| 처음에는 무엇을 눌러야 할지 몰랐지만 Space 조작은 쉬웠음 | 처음 몇 가지 조작을 직접 성공시키면 독립 사용에 도움이 된다. | 짧은 조작 연습형 튜토리얼 |
| 기능·명령어가 많아 처음 익히는 데 시간이 필요함 | 기본 조작부터 익히고 현재 상황에 필요한 명령을 찾아 들을 수 있어야 한다. | 기본 연습·상황별 도움말·전체 명령 안내의 구분 |
| 음성 명령이 제대로 전달됐는지 확인하고 싶음 | 음성을 들었다는 상태와 명령을 실행했다는 결과를 구분해 알려야 한다. | 인식한 동작·대상과 처리 결과 확인 |
| 단축키로 현재 프로그램·작업 상태와 기타 기능을 확인하고 싶음 | 조작 중에도 짧고 예측 가능한 경로로 상태와 도움말에 접근해야 한다. | 상태·최근 명령·도움말 확인 단축키 |
| 보호자의 강의 배정으로 학생 개인의 부담도 줄어든다는 의견 | 보호자의 사전 준비와 학생의 독립 수강을 연결하는 장점을 유지해야 한다. | 첫 배정 연습과 다음 방문의 학생 단독 수강 |
| 화면에만 있는 내용을 설명하는 기능이 유용함 | 핵심 가치인 시각 정보 보충은 유지해야 한다. | 화면 근거·원본 시각·다시 듣기 보존 |
| 안내가 길면 강의 흐름을 놓칠 것 같음 | 상황과 선호에 따라 설명량을 선택할 수 있어야 한다. | 짧은 안내와 원문 자세히 듣기의 분리 |
| 필요한 순간에만 멈춰 혼잡하지 않았다는 긍정 의견도 있음 | 현재 개입 방식의 장점을 유지하면서 긴 안내를 줄여야 한다. | 기존 동작을 비교 기준으로 유지하고 새 방식 평가 |
| 분석 중인지 오류인지 알기 어려움 | 작업 상태와 복구 행동이 한 번에 전달되지 않는 구간이 있다. | 일관된 상태 문구와 상태 확인 명령 |
| 학습 현황 확인은 유용하지만 학생의 독립성이 중요함 | 보호자의 안심과 학생의 선택권을 함께 설계해야 한다. | 저장된 학습 기록 요약과 선택형 도움 |

이번 체험은 안대를 착용한 사용 경험에 대한 의견이다. 초기 진입·조작 학습·음성 안내를 개선하는 근거로 사용한다. 실제 시각장애 학생의 장기 사용성이나 학습 효과는 후속 평가에서 확인한다. 음성과 타자를 함께 제공한다는 사실만으로 모든 장애 유형의 접근성을 입증한 것으로 해석하지 않는다.

참가자 수, 응답 묶음 사이의 중복 참가 여부, 실제 보호자 여부, 사용 기기, 과업별 소요 시간과 도움 횟수는 제공되지 않았다. 따라서 만족도·성공률·학습 효과의 현재 수치는 산출하지 않는다. 아래 수치는 개발 후 평가를 위한 제안 목표다.

## 3. 현재 구현과 개발할 부분

| 영역 | 현재 소스에서 확인한 구현 | 이번에 보완할 부분 |
| --- | --- | --- |
| 보호자 안내 | 첫 방문 설명서, 로그인·회원가입 선택, 설명서 다시 보기, 3단계 강의 준비 안내 | 긴 설명을 역할·연결·첫 배정의 과업별 안내로 나누고 실제 완료 상태와 연결 |
| 학생 안내 | 처음 사용 안내, 다시 보기, Space·타자·마이크 도움말 | 설명을 읽거나 듣는 것에 더해 실제 조작을 연습하고 성공 여부 확인 |

| 계정 연결 | 일회용 코드, 학생의 보호자 이름·공유 범위 확인과 동의 | 두 기기에서 누가 무엇을 해야 하는지, 어디까지 완료됐는지 명확하게 표시 |
| 해설·탐색 | 준비된 시점 설명, 짧은 요약, 문단·문장 읽기, 원래 위치로 복귀 | 짧게 듣기·자세히 듣기·요청할 때 듣기의 발견성과 마지막 해설 재청취 |

| 보호자 학습 현황 | 저장 위치와 기록 수 등 요약, 개인 메모 본문 비공개 | 데이터의 의미와 기준 시각을 분명히 설명하고 학생의 독립 수강을 기본 흐름으로 제시 |

따라서 “튜토리얼이 전혀 없다”를 구현 현황으로 기록하지 않는다. 피드백은 **기존 안내가 실제 첫 사용자의 행동을 충분히 도와주지 못한 경험**으로 받아들인다. 체험 당시 사용한 빌드가 현재 구현과 같은지도 다음 평가 전에 확인한다.

## 4. 우선순위와 개발 요구사항

P0는 다음 사용성 평가 전에 구현할 항목, P1은 P0 평가와 함께 보완할 항목이다. F1·F2 튜토리얼과 F3~F5의 상태·명령 확인을 우선 묶음으로 개발한다. 실제 사용자 참여는 초기 설계부터 시작하며 출시 판단의 필수 조건으로 둔다.

### F1. 학생 조작 연습형 튜토리얼 — P0

목표는 진행자의 구두 설명 없이 첫 재생·중지·타자 대체를 경험하게 하는 것이다.

첫 진입에서 “앱 음성 안내”, “외부 스크린리더”, “텍스트 중심 안내”를 고를 수 있게 한다. 기존 읽기 방식 설정을 재사용하고, 소리 시험은 사용자의 Enter·Space 등 명시적 시작 조작으로 실행한다. 브라우저의 자동 음성 재생을 전제로 설계하지 않는다.

연습은 사전 준비된 짧은 샘플로 제공한다. 처음에 “이 자료는 조작 연습용으로 준비한 샘플입니다”라고 구분하고 다음 순서로 진행한다.

1. **재생·일시정지:** Space 한 번을 누르고 실제 재생 상태 변화를 확인한다.
2. **전체 중지:** 재생·해설 중 Space 두 번을 눌러 두 출력이 멈추는 것을 확인한다.
3. **타자 대체:** Space 세 번으로 명령 창을 열고 “영상 중지” 같은 기존 명령을 실행한다.
4. **화면 설명과 복귀:** 준비된 설명을 선택해 듣고, 직접 재생하거나 탐색 전 위치로 돌아오는 방법을 연습한다.

단계마다 한 가지 행동만 안내한다. 기본 연습은 약 1~2분 안에 마칠 수 있도록 설계하되 시간 제한을 두지 않는다. 안내 다시 듣기·앞 단계·나중에 연습하기를 제공한다. 음성 명령과 마이크 권한은 선택형 추가 연습으로 분리한다.

음성 사용을 선택한 학생에게는 별도 분기로 기존 마이크 동의 → Space 길게 누르기 → 말하기 → 인식한 동작 확인 → 실행 결과 확인을 연습시킨다. 동의하지 않거나 음성 인식을 쓸 수 없으면 같은 과업을 타자로 수행한다. 사용 방식에 따라 완료할 수 있는 경로를 제공한다.

튜토리얼 뒤의 음성 안내서는 세 층으로 구성한다.

- **기본 조작:** 재생·정지, 전체 중지, 명령 창 열기를 짧게 다시 듣는다.
- **현재 화면의 도움말:** 지금 할 수 있는 대표 행동 2~3개와 명령 예시를 안내한다. 필기 중이면 필기·저장, 내용 찾기 중이면 문장·문단 탐색을 우선한다.
- **전체 명령 안내:** 수강·탐색·필기·설정별로 선택해 듣고 검색한다. 학생 확장에서 지원하는 명령만 포함한다.

“사용법”, “지금 할 수 있는 명령” 등의 도움말은 버튼·타자·허용한 음성 입력으로 다시 열 수 있게 한다. 전체 안내를 한 번에 길게 읽지 않고 사용자가 다음 항목과 상세 설명을 선택하게 한다.

완료는 실제 동작 이벤트로 확인하고, 설명 확인 버튼을 누른 것과 구분한다. 연습 단계는 계정·역할·안내 버전별로 기기에 저장해 이어갈 수 있게 한다. 다른 학생의 진행 상태를 가져오지 않고 기존 사용자를 매 방문마다 강제로 연습시키지 않는다.

**완료 조건:** 키보드만으로 연습을 끝내거나 나갈 수 있다. 나갔다가 다시 시작해도 강의 위치·필기·커서가 보존된다. 앱 TTS와 외부 스크린리더가 같은 본문을 중복 낭독하지 않는다. Space 횟수와 기존 입력 판정 시간, 입력칸의 일반 띄어쓰기는 변경하지 않는다.

### F2. 보호자·학생 연결 및 첫 배정 가이드 — P0

첫 화면에서 다음 관계를 짧게 설명한다.

> 보호자용은 연결과 강의 준비를 돕습니다. 학생용은 학생이 직접 강의를 듣고 필기하는 프로그램입니다. 처음 연결한 뒤에는 학생이 자신의 프로그램에서 학습합니다.

운영 환경의 첫 시작은 다음 과업으로 나눈다.

| 단계 | 보호자가 할 일 | 학생이 할 일 | 완료를 판단할 근거 |
| --- | --- | --- | --- |
| 1. 계정 준비 | 보호자용에서 가입·로그인 | 학생용에서 가입·로그인 | 각 역할의 정상 인증 |
| 2. 연결 요청 | 기존 일회용 연결 코드를 만들고 전달 | 학생용 연결 화면 열기 | 유효한 코드 발급 |
| 3. 연결 확인 | 학생 확인을 기다림 | 코드 입력 후 보호자 이름·공유 범위를 확인하고 동의 | 서버의 연결 완료 응답 |
| 4. 첫 배정 | 준비된 샘플을 선택해 배정 | 강의 목록을 갱신하고 열기 | 실제 배정 결과와 학생의 강의 열기 |

각 화면에는 현재 단계·지금 할 행동·상대 역할에서 할 행동을 표시한다. 코드 만료 시 새 코드 만들기, 학생에게 강의가 없을 때 연결·배정·공개 상태 확인 등 상황별 복구를 제공한다. “확인 중”과 “연결 완료”를 실제 서버 상태에 맞춰 구분한다.

가입 전에는 보호자용·학생용을 각각 어디에서 여는지 안내하고 서비스 접속을 확인한다. 서로 다른 컴퓨터에서 평가할 때는 양쪽 프로그램이 같은 접근 가능한 서비스에 연결되어 있어야 한다. 보호자 컴퓨터의 로컬 개발 주소를 학생 기기에서 그대로 쓰는 구성을 실사용 연결로 취급하지 않는다. 다른 기기의 설치·접속 여부는 실제 확인 근거가 있을 때만 완료로 표시한다.

로컬 시연의 보호자 학생 계정 생성 경로는 “로컬 시연용”으로 분리해 안내한다. 운영용 학생 가입·연결 절차와 혼합하지 않는다. 설명서에서 원본 파일이 학생 기기로 자동 전달되는 것처럼 표현하지 않는다.

학생 로그인 지원은 별도 선택 기능으로 유지한다. 연결 동의에 기기 로그인 지원 동의를 묶지 않으며, 이를 거절해도 강의 배정과 독립 수강이 가능해야 한다.

**완료 조건:** 기존 인증·연결 API·폼 이름을 바꾸지 않고 안내 흐름을 구성한다. 잘못된 코드·만료·학생 미확인·연결 완료를 구분한다. 보호자의 일방적인 학생 연결이나 동의 생략은 허용하지 않는다. 키보드만으로 연결과 샘플 배정을 마칠 수 있다.

### F3. 일관된 현재 상태 및 복구 안내 — P0

공통 상태 영역에 현재 작업과 바로 할 수 있는 다음 행동을 표시한다. 상태 문구는 실제 처리 이벤트와 정해진 문구를 조합하며, 안내 문장을 만들기 위한 생성형 모델 호출은 추가하지 않는다.

다음은 제안 문구이며 실제 분석 결과가 아니다.

| 실제 상태 | 안내 예시 | 사용자에게 제공할 행동 |
| --- | --- | --- |
| 학생 자료 열기 요청 대기 | “강의 자료를 여는 중입니다.” | 기다리기, 다른 강의 선택 |
| 사전 준비 샘플 열기 완료 | “연습용 자료를 열었습니다. 재생을 시작할 수 있습니다.” | 재생, 사용법 연습 |
| 재생용 등록만 완료 | “영상 분석은 실행하지 않았습니다. 원본 재생은 이용할 수 있습니다.” | 원본 연결, 준비 자료 확인 |
| 서버의 실제 분석 진행 | “강의 분석이 진행 중입니다.” | 현재 상태 확인, 나중에 결과 확인 |
| 불확실한 판독 | “세로축 단위를 확인하지 못해 설명을 보류합니다.” | 확인된 설명 듣기, 원문 확인 |
| 영상 연결 오류 | “영상 연결을 확인할 수 없습니다. 원본을 다시 연결해 주세요.” | 연결 다시 시도, 준비된 자료 읽기 |
| 필기 저장 실패 | “필기 저장에 실패했습니다. 초안은 이 기기에 남아 있습니다.” | 저장 재시도, 화면 유지 |
| 기기 초안 보존도 실패 | “초안도 보존하지 못했습니다. 화면을 유지하고 다시 저장해 주세요.” | 화면 유지, 저장 재시도 |

“현재 상태” 타자·음성 명령은 로컬 상태 조회로 처리한다. 강의를 열기 전에도 로그인·강의 선택 등 현재 필요한 행동을 설명할 수 있게 한다.

상태를 요청하면 현재 프로그램의 역할, 선택한 강의와 작업, 진행 중인 요청, 필요한 다음 행동을 짧게 안내한다. 예: “학생용 프로그램입니다. 필기 화면이며 저장을 기다리고 있습니다.” 또는 “보호자용 프로그램입니다. 학생 연결 확인을 기다리고 있습니다.” 확인할 수 없는 다른 컴퓨터나 운영체제 전체의 프로그램 실행 상태를 아는 것처럼 안내하지 않는다.

안내 우선순위는 다음 원칙으로 통일한다.

- 빠르게 끝나는 요청마다 시작·완료 음성을 연달아 재생하지 않는다. 지연 안내 기준은 초기값 1초로 두고 사용자 평가로 조정한다.
- 일반 상태는 강의를 임의로 멈추지 않으며, 외부 스크린리더에는 하나의 적절한 live region으로 전달한다. 요청한 해설이 재생 중이면 일반 초점 안내가 이를 끊지 않는다.
- 오류는 원인과 복구 행동을 한 번 전달한다. 저장 오류를 영상 연결 오류로 잘못 설명하지 않는다. 입력 중인 필기 초점을 빼앗지 않는다.
- 동일 상태의 반복 폴링을 반복 낭독하지 않는다. 계정·강의 전환 후 도착한 이전 작업의 상태는 버린다.
- 근거 없는 완료율·예상 대기 시간을 표시하지 않는다. 화면 닫기나 폴링 중단만으로 서버 분석까지 취소됐다고 안내하지 않는다.
- 재생 재개는 기존의 사용자 의도·중지 정책을 따른다. 오류 안내가 끝났다는 이유로 학생이 멈춘 강의를 다시 시작하지 않는다.

**완료 조건:** 정의된 상태 전이가 올바른 문구와 행동으로 연결된다. 중복 안내, 오래된 결과 덮어쓰기, 거짓 완료 표시가 없다. 상태 이벤트부터 읽기 영역 갱신까지의 지연과 실제 기기의 TTS 시작 지연은 따로 측정한다.

### F4. 음성 명령 인식·전달·실행 확인 — P0

학생이 “내 말이 전달됐는가”와 “원하는 기능이 실행됐는가”를 각각 확인할 수 있게 한다. 음성을 인식했다는 이유로 실행 완료를 알리지 않는다. 화면·짧은 앱 음성·외부 스크린리더 읽기 영역이 같은 상태를 설명하도록 한다.

| 단계 | 확인 근거 | 안내 예시 |
| --- | --- | --- |
| 듣기 준비 | 실제 음성 인식 시작 이벤트 | 짧은 시작음과 “명령을 말해 주세요.” |
| 인식·해석 | 최종 인식 결과와 지원 명령 매핑 | “‘10초 뒤로’ 명령으로 이해했습니다.” |
| 실행 또는 응답 대기 | 실제 동작 시작·요청 대기 상태 | “강의 위치를 이동하고 있습니다.” 또는 “질문 응답을 기다리고 있습니다.” |
| 실행 완료 | 실제 플레이어·저장·요청 결과 | “0분 20초로 이동했습니다.” 등 확인된 결과 |
| 미인식·불명확 | 최종 결과 없음, 지원 동작이나 대상 확인 불가 | “명령을 확인하지 못했습니다. 다시 말하거나 타자로 입력해 주세요.” |
| 실행 실패 | 실제 권한·연결·저장 오류 | “명령은 확인했지만 영상이 연결되지 않아 이동하지 못했습니다.” |

명확한 재생·일시정지·이동은 간결한 피드백과 함께 바로 실행한다. 인식과 완료를 짧은 한 안내로 합칠 수 있지만, 완료 표현은 실제 성공 후에만 사용한다. 중지 요청은 인식 확인 대화보다 우선 처리한다. 대상이 여러 개이거나 의미가 불명확하면 임의로 실행하지 않고 다시 말하기·타자 수정·선택을 제공한다. 삭제·연결 해제 등 기존 확인이 필요한 기능의 확인 절차는 유지한다.

마이크가 듣는 동안 인식 중간 결과를 매번 소리로 읽어 입력에 섞이지 않게 한다. 최종 인식 뒤의 확인은 명령 유형·대상·시점을 중심으로 짧게 제공한다. 개인정보·개인 필기·질문 본문이나 보류·정답 후보를 통째로 자동 반복하지 않는다. 시각 판독의 0.72 기준을 음성 인식 정확도의 검증된 기준으로 간주하지 않는다.

인식 내용을 고치고 싶을 때는 사용자가 선택해 확인·수정하는 타자 경로를 제공한다. 이때도 공개 금지 내용과 개인정보 처리 정책을 적용한다. 로컬에서 처리하는 명령은 해당 기능의 결과로 확인하고, 서버 요청은 요청 대기·실제 응답을 구분한다. 요청을 시작한 것만으로 서버가 처리를 완료했다고 표현하지 않는다.

“최근 명령 확인”에서 마지막으로 해석한 동작과 현재 처리 결과를 다시 확인할 수 있게 한다. 원본 녹음과 긴 인식 문장은 기본 저장하지 않고, 필요한 명령 요약은 현재 세션 안에서만 관리한다. 계정·강의 전환과 중지 후 도착한 이전 인식 결과가 실행되거나 현재 상태를 덮어쓰지 않아야 한다.

**완료 조건:** 미인식·중복 인식·마이크 거부·지원하지 않는 명령·네트워크 지연·실행 실패·실행 중 중지·계정 전환을 검사한다. 하나의 발화로 같은 동작이 중복 실행되지 않는다. 학생이 인식 결과와 실행 결과를 각각 확인하고 타자로 전환할 수 있다. 확인 안내에 생성형 모델 호출을 추가하지 않는다.

### F5. 상태·최근 명령·도움말 단축키 — P0, 추가 기능 확장은 P1

단축키는 다음 세 기능부터 제공한다. 실제 키 조합은 Windows/macOS·Chrome·VoiceOver/NVDA·한글 입력기 충돌 검사 후 확정하고 사용자가 확인·변경할 수 있게 한다. 이 기획 단계에서 검증하지 않은 조합을 기본 단축키로 확정하지 않는다.

| 단축 기능 | 실행 결과 |
| --- | --- |
| 현재 상태 확인 | 학생용/보호자용 역할, 현재 작업, 처리 상태와 다음 행동을 짧게 안내 |
| 최근 명령 확인 | 직전 명령의 해석과 실행 완료·대기·실패 결과를 안내 |
| 현재 화면 도움말 | 사용할 수 있는 대표 명령과 버튼 2~3개를 안내하고 상세 안내 진입 제공 |

키 조합을 기억하지 못할 때도 같은 기능을 이름 있는 버튼과 타자 명령으로 사용할 수 있게 한다. 튜토리얼에서 각 기능을 한 번 실행해 보게 하고 설정에서 현재 할당을 다시 확인하게 한다.

기본 적용 범위는 각 확장 화면에 초점이 있는 경우다. 확장 밖에서 돌아올 때는 기존 학생 패널 열기 경로를 안내한다. 기존 학생 패널 열기 `Alt+Shift+S`, 전체 중지 `Alt+Shift+X`, Space 1·2·3회와 길게 누르기, Esc·F6·Tab 이동은 보존하고 실제 기기에서 함께 검사한다. 기존 키 조합도 모든 환경에서 충돌 없이 동작한다고 전제하지 않는다.

음성·텍스트 입력란의 문자 입력, 한글 조합, 브라우저·스크린리더의 기본 키를 가로채지 않는다. 입력 중 상태를 요청해도 작성 본문·커서·탐색 위치를 바꾸지 않는다. 짧은 상태 안내 후 재생은 기존 사용자 의도를 따른다. 원래 일시정지한 강의를 자동 재생하지 않는다.

**완료 조건:** 버튼·키보드·타자 경로가 같은 상태와 도움말을 제공한다. 실제 VoiceOver/NVDA·한글 입력·브라우저 이동과 충돌하지 않는 할당을 기록한다. 보호된 외부 강의 페이지에 새 키 가로채기를 설치하지 않는다.

### F6. 짧은 해설·원문 자세히 듣기·마지막 해설 다시 듣기 — P1

기존 해설과 탐색 기능을 다음 세 가지 선택으로 쉽게 찾게 한다.

- **짧게 듣기:** 학습에 필요한 차이와 위치를 먼저 전달한다.
- **자세히 듣기:** 검증된 전체 설명·원문을 요청한 범위로 읽는다.
- **요청할 때 듣기:** 자동 개입을 끄고 기존 설명·문장·문단 조작을 직접 사용한다.

짧은 해설은 검증된 구성요소와 정해진 표현으로 만든다. 단순 화면의 핵심 안내는 약 5~10초를 초기 설계 목표로 삼되, 길이 제한 때문에 부등호·부호·숫자·단위·축 이름·조건을 잘라내지 않는다. 정확성에 필요한 경우 더 길게 설명한다.

긴 지문은 “긴 지문이 있습니다. 전체 또는 밑줄 부분을 선택해 들을 수 있습니다”처럼 접근 방법을 먼저 알리고, 전체 원문·문단·문장·강조 부분은 온전히 보존한다. 짧은 안내로 원문 읽기를 대체하지 않는다.

“마지막 해설 다시 듣기”는 현재 강의에서 마지막으로 제공한 공개 가능한 설명을 다시 읽는다. 원본 시각을 함께 안내하고, 계정·강의가 바뀌거나 근거가 철회·보류되면 재사용하지 않는다. 검증된 설명 ID·원본 시각을 기준으로 하고 후보 원문을 별도로 저장하지 않는다. 재청취·준비된 요약·문단 낭독에 새 모델 호출을 붙이지 않는다.

강사가 같은 정보를 이미 전달했다면 기존 `INDEX_ONLY` 판단을 유지한다. 같은 장면의 발화와 화면을 자동으로 독립된 진실 두 개로 취급하지 않는다. 설명할 중요한 차이가 있을 때의 개입을 보존한다.

**완료 조건:** 기존 방식과 같은 강의·장면으로 비교해 핵심 정보 누락과 시점 오류가 없다. 낮은 확신도와 문제 정답 노출은 0건이다. 새 짧은 방식을 먼저 선택형으로 평가하고 통과한 범위에서 기본값 변경을 결정한다.

### F7. 학생의 독립 수강과 보호자의 필요한 지원 — P1

학생의 다음 방문 기본 과업은 로그인 상태 확인 → 최근 또는 배정된 강의 선택 → 원본 연결 확인 → 직접 재생이다. 이미 익힌 튜토리얼을 반복 통과하거나 보호자가 승인해야만 수강할 수 있는 단계를 추가하지 않는다. 개인 필기와 읽기 방식·설명량 선택을 보존한다.

보호자의 강의 준비·배정으로 학생이 매번 강의를 찾아 등록하는 수고가 줄어든다는 장점을 유지한다. 이 부담 감소가 실제로 나타나는지는 준비·수강 과업의 단계 수와 도움 요청으로 확인한다. 학생의 선택권을 줄이거나 보호자의 상시 확인을 추가하는 방식으로 해결하지 않는다.

보호자 화면은 연결 상태·배정 여부·최근 저장된 위치와 기록 시각을 중심으로 안내한다. 재생 위치를 이해도·학습 완료율·현재 실시간 접속 상태로 바꾸어 표현하지 않는다. 학생의 필기·질문 본문은 보호자에게 새로 공유하지 않는다.

학생이 도움을 요청할 때는 현재 오류 유형과 다음 행동을 확인할 수 있게 한다. 자동 감시·상시 알림·외부 메신저 전송을 기본 기능으로 추가하지 않는다. 도움이 필요한 경우에도 학생의 학습 위치와 작성 내용을 보존한다.

**완료 조건:** 초기 연결을 마친 뒤 보호자 조작 없이 학생이 수강·중지·부분 재청취·필기 저장을 완료한다. 원격 로그인 지원을 사용하지 않는 학생도 같은 학습 기능에 접근한다.

이번 범위에서 제외하는 것은 기존 Space 체계를 대체하는 새 제스처 체계, 발표문·암기표 등 제거된 생성 도구의 재도입, 학생 필기 AI 재작성, 원본 자동 공유, 보호자의 실시간 학생 감시, 전면 웹 리디자인이다. 상태·명령 확인과 도움말 단축키는 이번 범위에 포함한다.

## 6. 실행 계획: 4주 목표, 검증·수정 1~2주 완충

개발 1명과 UX·접근성 검토 협업이 가능한 경우의 제안 일정이다. 추가된 음성 명령 확인과 단축키 검증을 포함해 1차 평가 빌드는 4주를 목표로 하고, 실제 사용자 모집·기기 확보·충돌 수정에 필요한 1~2주를 완충 기간으로 둔다.

| 기간 | 주요 작업 | 주간 산출물·판정 |

## 7. 사용자 평가 설계와 성공 지표

초기 파일럿은 실제 시각장애 학생 5~8명과 실제 보호자 3~5명을 모집하는 안을 제안한다. 모집 규모는 조정할 수 있으며 이 규모만으로 전체 사용자에게 일반화하지 않는다. 전맹·저시력, 스크린리더 숙련도, 기기와 사용 방식의 차이를 기록하고 결과를 나눠 본다. 참여 동의·중단 선택을 보장하고 개인 계정·개인 강의가 필요 없는 연습 자료를 제공한다.

진행자는 과업만 제시하고 조작 방법을 먼저 알려주지 않는다. 앱 안의 사용법·다시 듣기를 스스로 이용한 것은 독립 수행으로 본다. 진행자가 직접 키·위치를 알려준 도움은 별도로 기록한다. 연결 과업은 두 역할의 협력이 필요한 초기 설정으로, 이후 학생의 독립 수강 과업과 따로 평가한다.

기록은 익명 참가자 코드, 역할·사용 방식·기기, 과업 ID, 성공 여부·시간·도움 횟수·오류 유형을 중심으로 한다. 개인 필기·질문 본문·비밀번호·API 키·원본 강의·마이크 녹음을 기본 수집 항목에 넣지 않는다. 문제를 재현할 때는 동의한 시험 자료를 사용하고, 앱 안의 연습 진도 기록과 별도 연구용 평가 기록을 구분한다.

## 8. 다음 버전 반영 조건

- P0의 시작·연결·상태 안내를 키보드만으로 완료하고, 중간에 나갔다가 안전하게 다시 시작할 수 있다.
- 인식한 명령·실행 대기·완료·실패를 구분하고, 미인식·중복 결과·중지·화면 전환 후 잘못된 실행이 0건이다. 인식 확인을 실행 성공으로 오안내하지 않는다.
- 현재 상태·최근 명령·상황별 도움말에 단축키와 버튼·타자 대체로 접근하며, 실제 기기의 입력기·브라우저·보조기술 충돌을 기록하고 해결한다.
- 앱 음성 모드와 실제 VoiceOver/NVDA 사용 흐름을 각각 평가한다. 자동 axe·접근성 트리·합성 이벤트 검사와 실제 청취 결과를 구분한다.
- 신규 동작의 단위·API·설치 브라우저 회귀를 추가하고, 기존 `verify_all.sh`·확장 종합 검사·기존 웹 흐름을 통과한다. 기존 테스트를 삭제해 통과시키지 않는다.
- 1280px·390px 캡처, 키보드 초점·live region, 보호자 연결→샘플 배정, 학생 첫 수강과 오류 복구를 기록한다. 검사 범위의 axe 위반은 0건이어야 한다.
- 중요한 화면 정보 누락·시점 오류·필기 유실·정답 및 보류 내용 노출이 발견되면 해당 변경을 보완한다. 검증이 끝나지 않은 새 해설 방식은 기존 기본 동작을 유지한 선택형 평가 경로로 둔다.
- 실제 영상 분석·외부 사이트·마이크·모델 답변 품질은 해당 환경에서 확인한 범위만 구현·시연 설명에 반영한다. 사전 준비 샘플을 업로드 영상 분석으로 표시하지 않는다.

현재 자동 검증 기록은 [전체 기능 검사 보고서](verification/2026-11-16-full-health-check/REPORT.md)에 있다. 이 기획안의 신규 기능이나 실제 사용자 평가가 완료됐다는 근거로 사용하지 않는다.
