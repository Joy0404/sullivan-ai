# Sullivan AI 피드백 기반 개발 기획안 v2.2

작성일: 2026-11-16 · 최종 수정: 2026-11-17 · 버전: 토큰·비용·응답 효율 기준 보완 및 첫 구현 · 상태: 선택형 실습·고정 안내 구현, 로컬 전체 회귀 통과, 실제 사용자·모델 평가 대기

기준: 제공된 전체 학생·보호자 피드백, 기존 기획안 v1.1, 검증된 `final`의 `6b01f75`와 현재 소스. 기획의 전체 10개 절을 유지해 호출 없는 안내를 우선 구현했다. 기존 인증·API 계약·모델 설정과 웹 학생 화면은 보존한다.

## 1. 검토 결론과 수정 이유

**튜토리얼 중심의 방향은 적절하다. 첫 버전의 목표는 “진행자의 조작 설명 없이 첫 수강을 시작하고, 내 명령의 처리 결과를 알 수 있게 하기”로 좁힌다.**

**튜토리얼·도움말·상태 확인·명령 확인을 추가해도 생성형 모델 요청은 늘리지 않는다.** 준비된 공개 자료와 로컬 상태·정해진 문구를 재사용한다. 모델이 필요한 강의 질문과 실제 분석은 품질·보호 정책·재시도 포함 사용량을 함께 검증한다.

피드백은 역할 분리·강의 배정·Space·음성/타자 대체의 가치를 지지한다. 반복해서 등장한 문제는 처음 배우는 부담과 안내 부족이다. 튜토리얼을 추가하는 동시에 가입·연결의 다음 행동과 명령 결과를 명확히 해야 한다.

기존 안에서 보완할 부분은 다음과 같다.

| 검토 항목 | v1.1의 위험 | v2.0의 결정 |
| --- | --- | --- |
| 첫 버전 범위 | 튜토리얼·명령 확인·상태·새 단축키·설명량 변경이 동시에 필요해짐 | 첫 버전은 역할별 시작 안내와 공통 상태·도움말에 집중 |
| 학습 부담 | 명령이 많다는 의견에 단축키·설정이 더 늘 수 있음 | 기본 조작 3개, 공통 버튼 2개부터 시작하고 상세 안내는 선택 |
| 튜토리얼 진입 | 로그인·강의 없이도 실제 재생 연습이 가능한 것처럼 계획됨 | 로그인 전 안내와 로그인·샘플 배정 후 실제 연습을 분리 |
| 음성 피드백 | 명령마다 인식·실행·완료를 따로 읽으면 조작이 느려짐 | 빠른 명령은 성공 후 한 번, 지연·실패만 추가 안내 |
| 상태 안내 | 현재 음성 경로는 안내 중 영상 정지·재개에 관여함 | 상태 표현과 음성 우선순위를 먼저 정하고 기존 중지·재개 정책 검증 |
| 연결 완료 | 보호자가 학생의 실제 화면 열기까지 확인할 수 있다고 오해할 수 있음 | 연결·배정은 서버 근거, 학생 화면 열기는 학생 기기의 근거로 각각 표시 |
| 평가·일정 | 작은 표본의 90% 목표와 4주 일정이 확정 기준처럼 읽힐 수 있음 | 공학적 필수 조건과 사용자 개선 지표를 분리하고 작업량·전제 조건 제시 |
| 토큰·처리 효율 | 안내·명령 해석까지 모델에 맡기면 호출·지연·비용이 늘 수 있음 | 기본 조작은 생성 요청 0회, 실제 질문·분석의 근거 축소는 실험 경로와 실측 게이트 적용 |

“학생 개인의 부담이 줄어든다”는 긍정 의견은 보호자의 사전 준비와 학생의 독립 수강을 이어주는 장점으로 유지한다. 보호자에게 학생의 상시 감시나 매번의 수강 승인을 요구하는 구조는 추가하지 않는다.

## 2. 첫 버전 범위와 후속 개발

### 2.1 첫 버전: 세 가지 묶음

| 묶음 | 포함할 기능 | 이번 버전의 완료 모습 |
| --- | --- | --- |
| 학생 시작 연습 | 기본 Space 조작·타자 대체, 선택형 음성 입력 연습, 안내 재진입 | 샘플을 열고 재생·중지·명령 실행을 직접 성공시킴 |
| 보호자 시작 안내 | 가입·로그인·학생 확인·연결·첫 샘플 배정의 다음 행동 | 누가 어느 프로그램에서 무엇을 해야 하는지 확인하며 첫 배정을 마침 |
| 공통 확인·도움 | 실제 상태와 최근 명령 결과, 현재 화면에서 가능한 행동 | “현재 상태”와 “사용법”을 버튼·키보드·타자·허용한 음성 입력으로 확인 |

공통 조작은 **현재 상태**, **도움말** 두 버튼으로 시작한다. 최근 명령 결과는 현재 상태 안에서 확인하고, “최근 명령” 타자·음성 요청도 같은 정보를 사용한다. 기능마다 별도 상태창과 단축키를 만들지 않는다.

### 2.2 후속 개발

- **추가 단축키:** 상태 확인용부터 검토한다. Windows/macOS·Chrome·VoiceOver/NVDA·한글 입력기 충돌 검사를 통과한 조합을 정하고 변경·해제할 수 있게 한다. 첫 버전에는 기존 패널 열기와 버튼의 키보드 접근을 보장한다.
- **전체 명령 안내:** 첫 버전의 상황별 대표 명령을 바탕으로 분야별 탐색·검색을 확장한다. 지원하는 명령만 표시한다.
- **새 설명량 선택과 마지막 해설 재청취:** 기존 준비된 설명·짧은 요약·문장/문단 읽기를 먼저 쉽게 찾게 한다. 새로운 짧은 해설을 기본으로 바꾸는 일은 별도 품질 비교 후 진행한다.

기존 Space 횟수·길게 누르기·입력 판정 시간, Esc·F6·Tab, 학생 패널 열기와 전체 중지 단축키는 보존한다. 기존 웹 학생 화면·CSS·함수·쿠키 인증, 기존 유효 API 계약과 Gemini 설정은 이번 변경 범위에서 유지한다.

v1.1의 F1·F2는 역할별 튜토리얼로, F3·F4는 공통 상태·명령 확인으로 우선 구현한다. F5의 추가 키 할당과 F6의 새 해설 방식은 후속 단계다. F7의 독립 수강은 첫 버전 전체의 수락 기준으로 적용한다.

## 3. 역할별 실제 사용 흐름

### 3.1 공통 진입: 짧은 안내 후 선택

첫 진입에서 역할과 목적을 한 문장으로 안내하고 “시작 안내”, “로그인해서 계속”, “도움말”을 제공한다. 길게 읽어야만 가입·로그인할 수 있는 구조는 피한다. 기존 사용자의 다음 방문에는 매번 튜토리얼을 강제하지 않는다.

앱 음성·외부 스크린리더·텍스트 중심 사용은 기존 읽기 방식 설정을 재사용한다. 브라우저의 자동 음성 시작을 전제로 하지 않고 이름이 분명한 음성 시작·시험 버튼을 키보드로 사용할 수 있게 한다.

### 3.2 보호자: 가입부터 첫 배정까지

1. **역할 확인:** 보호자용은 계정 연결·강의 준비와 배정을, 학생용은 학생 자신의 수강을 담당한다고 안내한다.
2. **가입·로그인:** 계정이 있는 사용자와 처음 만드는 사용자를 구분한다. 복구 코드 보관 등 기존 절차를 보존한다.
3. **연결 코드 전달:** 기존 일회용 코드를 만들고 학생에게 전달한다. 다음 행동을 “학생용 프로그램에서 입력”으로 명확히 표시한다.
4. **학생 확인:** 학생은 자기 프로그램에서 로그인하고 보호자 이름·공유 범위를 확인한 뒤 동의한다. 보호자 화면은 실제 연결 응답 후 완료로 바뀐다.
5. **샘플 배정:** 처음에는 사전 준비 샘플을 선택해 배정한다. 보호자 화면의 완료는 서버의 배정 성공을 의미한다.
6. **학생의 첫 수강:** 학생은 자기 목록에서 배정된 샘플을 연다. 열기·재생 성공은 해당 학생 기기에서 확인한다.

각 단계는 “완료”, “내가 할 일”, “상대 역할에서 할 일”을 구분한다. 코드 만료·이미 연결됨·연결 해제·통신 실패에는 다음 행동을 제시하고 완료된 계정 설정을 처음부터 반복시키지 않는다.

다른 기기의 설치·실행·학생 화면 열기를 직접 확인할 근거가 없으면 보호자에게 확인됐다고 표시하지 않는다. 저장된 위치는 기준 시각과 함께 보여 주고 이해도·학습 완료율·실시간 감시로 표현하지 않는다.

운영 환경의 학생 직접 가입·동의와 로컬 시연의 보호자 시험 계정 생성은 구분한다. 보호자의 학생 로그인 지원은 기존 별도 동의를 유지하며 첫 연결의 필수 조건으로 만들지 않는다. 서로 다른 컴퓨터에서는 양쪽 확장이 같은 접근 가능한 서비스에 접속하는지 먼저 확인한다.

### 3.3 학생: 준비 상태에 따른 연습 진입

현재 코드의 강의 재생·명령은 학생 인증과 선택한 강의를 전제로 한다. 따라서 첫 버전에서는 **학생이 이미 배정받은 사전 준비 샘플**에서 실제 연습을 진행한다. 학생이 임의로 샘플을 자기 계정에 배정하는 신규 API를 만들거나 인증을 흉내 내지 않는다.

| 학생의 현재 상태 | 제공할 안내·행동 |
| --- | --- |
| 로그인 전 | 역할·기본 키·음성 시작·타자 대체를 설명하고 로그인으로 안내 |
| 로그인했지만 샘플이 없음 | 사용법을 열람하게 하고 연결·샘플 배정이 필요한 이유와 다음 행동 안내 |
| 연습 가능한 샘플이 배정됨 | “조작 연습 시작”을 학생이 선택해 실제 연습 |
| 이미 다른 강의를 수강·필기 중 | 시작 전 위치·미저장 기록을 보존하고 기존 전환·저장 실패 처리 적용 |
| 연습 중 종료하거나 실패함 | 완료한 단계는 보존하고 해당 단계에서 재시도·설명 보기·나가기 제공 |

샘플이 없어 실제 동작을 하지 못한 단계는 “설명 확인”으로만 기록한다. 재생 연습 완료로 계산하지 않는다. 샘플은 “사전 준비된 연습 자료”로 표시하고 학생이 선택한 영상을 새로 분석한 것으로 설명하지 않는다.

### 3.4 학생 연습: 기본 세 단계와 선택형 음성 분기

한 단계에 한 가지 행동을 제시하고 실제 결과로 확인한다.

| 단계 | 연습 | 성공 근거 |
| --- | --- | --- |
| 1. 재생·일시정지 | Space 한 번 사용 | 실제 플레이어 상태 변화 |
| 2. 전체 중지 | Space 두 번 사용 | 영상·앱 음성·진행 요청이 기존 정책대로 중지 |
| 3. 타자 명령 | Space 세 번 → “영상 중지” 등 기존 명령 실행 | 실제 명령 처리 결과와 입력창의 정상 종료 |

음성 사용을 선택하면 기존 마이크 동의 뒤 Space 길게 누르기 → 시작 신호 확인 → 말하기 → 인식한 동작과 실행 결과 확인을 연습한다. 동의를 거절하거나 인식을 사용할 수 없으면 타자로 같은 과업을 마칠 수 있다.

연습 안내는 “설명 → 시도 → 결과 → 다음 단계” 순서다. 약 1~2분은 안내 분량을 설계하는 목표이며 사용자에게 시간 제한을 주지 않는다. 각 단계의 다시 듣기·재시도·나중에 하기와 시작 화면의 안내 재진입을 제공한다.

문단·문장·필기 등 자세한 기능은 사용자가 해당 작업을 열었을 때 대표 명령 2~3개부터 안내한다. 첫 연습에서 전체 기능을 읽거나 외우게 하지 않는다.

## 4. 명령 피드백과 음성 출력 규칙

### 4.1 인식·대기·완료를 구분한다

| 상황 | 기본 동작·문구 예시 | 하지 않아야 할 오안내 |
| --- | --- | --- |
| 실제 인식 시작 | 시작 신호와 듣기 상태 표시 | 마이크 준비 전에 듣고 있다고 표시 |
| 명확한 빠른 조작 성공 | 바로 실행한 뒤 “일시정지했습니다” 등 한 번 안내 | 인식·실행·완료를 모두 길게 반복 |
| 동작이 지연됨 | 필요한 경우 “‘위치 이동’ 명령을 처리 중입니다” | 요청 시작을 성공으로 표시 |
| 동작 실패 | “명령은 확인했지만 영상이 연결되지 않아 이동하지 못했습니다” | 실패했는데 완료라고 말하기 |
| 미인식·지원하지 않는 명령 | 다시 말하기·타자 수정·현재 도움말 제공 | 불명확한 동작을 임의 실행 |
| 대상이 불명확함 | 필요한 대상만 다시 선택·확인 | 추측한 강의나 문단으로 이동 |
| 중지 | 기존 중지를 즉시 처리하고 짧게 확인 | 중지 전에 인식 확인 대화 요구 |

삭제·연결 해제 등 기존 확인 절차는 유지한다. 모든 명령에 “맞나요?”를 추가하지 않는다. 사용자가 말한 내용과 해석한 동작을 확인할 필요가 있으면 최근 명령에서 짧은 동작·대상·시점 요약을 제공하고 타자 수정으로 이어지게 한다.

인식 중간 결과를 매번 읽지 않는다. 마이크가 듣는 동안 앱 TTS가 인식에 섞이지 않게 한다. 음성 인식의 판단 기준은 시각 판독의 confidence 0.72와 별개로 검증한다. 개인 필기·질문 원문·개인정보·정답·보류 후보를 확인 안내에서 통째로 자동 반복하지 않는다.

### 4.2 최소 공통 상태

명령 상태는 `듣는 중`, `해석됨`, `처리 중/응답 대기`, `성공`, `실패`, `취소`를 구분한다. 실제 성공 근거가 없는 상태는 성공으로 넘기지 않는다. 상태 조회는 역할·현재 작업·진행 중 요청·최근 명령 결과·다음 행동을 짧게 조합한다.

예: “학생용, 필기 화면입니다. 강의는 일시정지됐고 필기를 저장하는 중입니다.” 예: “보호자용입니다. 학생 연결을 기다리고 있습니다.” 이 문구는 설계 예시다.

자동 저장과 수강처럼 동시에 진행되는 작업을 하나의 전역 “작업 중” 값으로 뭉개지 않는다. 사용자가 요청한 명령과 중요한 실패를 우선 보여 주고, 관련 자동 저장 상태를 필요한 경우 덧붙인다. 다른 기기나 운영체제 전체의 프로그램 상태를 탐지하는 기능은 포함하지 않는다.

### 4.3 안내가 학습을 방해하지 않게 한다

- 일반 자동 저장·반복 폴링은 상태가 바뀔 때 읽기 영역을 갱신하고 매번 앱 음성으로 읽지 않는다.
- 사용자가 요청한 상태·도움말은 짧게 읽고 상세 내용은 선택하게 한다. 읽기 영역은 숨겨진 작업 안으로 들어가지 않게 한다.
- 외부 스크린리더 모드에서는 앱 TTS를 끄고 같은 정보를 하나의 적절한 live region으로 전달한다.
- 전체 중지는 즉시 우선한다. 명령을 듣는 동안 다른 안내가 끼지 않게 하고, 일반 초점 안내는 요청한 자료 읽기를 끊지 않게 한다.
- 저장·연결 실패는 실제 영향과 복구 행동을 구분한다. 입력 초점을 오류 영역으로 강제로 이동시키거나 학생 본문을 다시 쓰지 않는다.
- 실제 음성 안내가 영상을 일시정지해야 하면 기존 재생 의도와 중지 세대를 적용한다. 원래 정지한 영상이나 중지 이후의 늦은 응답을 자동 재생하지 않는다.

현재 `StudentSpeech.say()`는 음성 출력과 영상 정지·재개를 함께 다룬다. `status()`는 공통 상태 이벤트를 발행하고 학생 안내기가 이를 받을 수 있다. 따라서 새로운 상태 문구를 추가하기 전에 **어떤 상태를 화면·live region·앱 음성 중 어디로 보낼지** 명세하고 기존 출력 경로를 테스트해야 한다.

## 5. 구현 방식과 개발 티켓

### 5.1 상태·명령·안내의 공통 원본

화면별로 별도 성공 판단과 안내 문구를 만들지 않는다. 명령의 ID·지원 범위·안내 예시·현재 사용 가능 조건을 같은 명세에서 관리하고 기존 명령 분류 및 실행 경로와 일치시키는 회귀를 둔다. 학생 확장에서 제거된 생성 도구를 도움말에 다시 노출하지 않는다.

튜토리얼은 기존 동작을 호출하고 같은 처리 결과를 관찰한다. 키를 눌렀다는 이유만으로 성공 처리하거나 샘플 데이터로 실행 결과를 흉내 내지 않는다.

각 요청은 계정·강의·화면의 세대와 작업 ID를 가진다. 예전 작업 결과는 현재 화면·튜토리얼·최근 명령을 바꾸지 못한다. 재생·이동은 플레이어 결과, 저장은 서버 응답, 배정·연결은 해당 서버 응답을 근거로 완료한다.

연습 진행에는 역할·계정·안내 버전·단계별 `미시도/실습 완료/나중에 하기`만 기기에 보존한다. 설명서는 기존 `onboarded`로 확인하며 실습 진도와 분리한다. 로그인 전 일반 설명 기록과 로그인 후 개인 연습 기록을 구분한다. 설명서 확인 여부를 현재 연결·배정 완료의 근거로 사용하지 않는다. 기존 `onboarded`와 안내 확인 값을 일괄 초기화하지 않는다.

## 6. 토큰·비용·응답 효율 설계

### 6.1 기능별 호출 원칙

| 기능 | 처리 경로 | 생성형 모델 요청 기준 |
| --- | --- | --- |
| 튜토리얼·사용법·현재 화면의 대표 명령 | 버전 관리한 안내와 지원 명령 목록 | 0회 |
| 현재 상태·최근 명령·인식 및 실행 확인 | 실제 로컬/서버 결과와 정해진 문구 | 0회 |
| 재생·정지·이동·단축키 | 기존 명령 분류와 플레이어 조작 | 0회 |

여기의 0회는 Gemini 등 생성 모델 요청 수다. 브라우저의 기존 음성 인식·TTS, 인증·저장 통신, 기기 처리까지 모두 무료이거나 자원이 들지 않는다는 의미는 아니다. 음성 처리 경로와 권한·지원 상태는 별도로 확인한다.

명확한 조작·안내는 기존 로컬 분류로 처리한다. 불명확한 조작 명령은 다시 말하기·타자 수정·도움말로 연결한다. 지원하지 않는 명령을 매번 질문 모델에 보내 해석시키지 않는다. 실제 학습 질문은 조작 명령과 구분해 기존의 허용·근거 확인 절차를 따른다.

### 6.2 자료 선택과 재사용

- 질문에는 현재 요청에 필요한 검증 원문·근거 ID·원본 시각을 우선 사용한다. 현재 화면 질문은 해당 시점 주변, 이전·비교·후반 질문은 강의 전체에서 관련 근거를 찾는다. 전체 강의나 모든 대화 이력을 매번 무조건 첨부하지 않는다.
- 근거가 부족하면 범위를 넓히고, 그래도 부족하면 보류한다. 토큰 한도에 맞추려고 부등호·단위·조건·원문을 중간에서 자르거나 검증되지 않은 요약으로 대체하지 않는다.
- 준비된 공개 snapshot의 탐색 인덱스는 해당 버전 안에서 재사용한다. 재렌더링·재청취·상태 조회마다 같은 본문을 다시 구조화하거나 분석하지 않는다.
- 재사용 범위는 계정·강의·공개 자료 버전·문제 모드·현재 접근 권한에 묶는다. 계정 전환·배정 철회·원문/정책 변경 시 관련 결과를 무효화하고 현재 안전 경계를 다시 적용한다.
- 새 질문 답변의 유사도 캐시나 사용자 간 공유 캐시는 첫 버전에 추가하지 않는다. 공급자 캐싱을 새로 설정하는 작업도 별도 검토로 둔다. 원본 영상·학생 필기·질문 본문을 캐시하기 위해 새로 영속 저장하지 않는다.

### 6.3 중복 요청과 재시도

하나의 확정 발화는 한 동작으로 처리하고, 인식 중간 결과·키 반복·중복 클릭·상태 폴링이 생성 요청을 만들지 않게 한다. 같은 계정·강의·요청이 이미 처리 중이면 기존 진행 상태를 보여 준다. 명시적으로 다시 듣기를 요청한 경우에는 동일한 자료라도 다시 읽을 수 있어야 한다.

질문 최적화 경로는 기존 실험의 최초 응답과 필요한 경우 한 번의 근거 확대 재시도를 기준으로 검토한다. 다른 말로 질문을 반복 생성하는 자동 루프는 추가하지 않는다. 전체 검증으로 돌아가는 분석 경로와 계획된 자료 검증 요청은 안전을 위해 유지하며 사용량에 모두 포함한다.

화면에서 취소했거나 오래된 결과를 버렸다는 이유로 공급자 비용이 없어졌다고 계산하지 않는다. 이미 실행된 실패·취소 관련 요청과 재시도도 계측한다. 처리 한도·연결 실패 시에는 검증된 준비 자료와 기본 수강 기능을 유지하고, 설명 문구를 만들기 위한 추가 모델 호출은 하지 않는다.

### 6.4 기존 최적화 코드의 반영 단계

현재 저장소에는 요청별 사용량 계측, 질문 근거 선택, 구간 중심 재검증과 비교 도구가 있다. 재생·준비된 자료 읽기는 기존 호출 없는 경로를 유지한다. 구간 검증과 근거 선택의 실험 경로는 실제 모델 품질·총토큰 비교가 남아 있으므로 제출 기본값으로 전환하지 않는다.

1차 전체 영상 탐색은 기준으로 유지한다. 2차 구간 검증은 후보 주변 범위·겹치는 구간 병합을 사용하되 긴 지문·이어지는 판서·음성 대조에는 범위를 넓힌다. 실제 입력 구간 지원이나 근거가 부족하면 전체 검증으로 돌아간다. 추가 자료 감사와 전체 검증 재시도의 비용을 빼고 절감으로 보고하지 않는다.

2차 시각 재판독에는 후보 ID·원본 시각·위치와 필요한 범위를 보내고 화면을 직접 다시 읽게 한다. 서버가 ID로 두 판독을 비교하며, 응답은 재판독 원문·시각·화면 근거·상태·수정 사항 중심으로 제한한다. 1차 전체 판독·해설을 그대로 반복하거나 전체 결과 객체를 다시 생성하는 일을 줄이되 자막·지문·복습 자료의 모순 검증은 유지한다.

해당 작업은 MVP 기능 추가와 분리한 **OPT-01: 기존 실험 경로의 동일 조건 실측·품질 승인**으로 관리한다. 자체 제작/이용 권한이 있는 자료, 공급자 연결, 비용 한도와 평가자가 준비됐을 때 실행한다. 실측이 없는 동안에도 MVP의 안내·조작에서 생성 요청 0회는 모의 공급자 경계와 네트워크 관찰로 검증할 수 있다.

| 지표 | 기록·판정 기준 |
| --- | --- |
| 안내·조작의 생성 요청 수 | 위 0회 대상에서 0회. 모델 연결이 설정된 시험에서도 의도치 않은 호출이 없어야 함 |
| 단계별 사용량 | 분석·검증·질문별 입력·출력·추론·캐시·총토큰과 성공·시도·재시도 기록 |
| 실제 총토큰 | 계획된 추가 검증·실패·대체 경로·재시도를 모두 합산. 공급자 총계에 추론·캐시를 다시 더하지 않음 |
| 응답 효율 | 상태 영역 갱신, 실제 동작 완료, 모델 응답, 실제 TTS 시작 시간을 구분. 같은 과업의 중앙값·상위 지연과 실패·타임아웃 건수 함께 기록 |
| 중복·로컬 처리 | 확정 발화당 실행 수, 동일 진행 요청의 중복 수, 자료 인덱스 재생성 수와 API 조회 수 확인 |
| 비용 | 확인 가능한 공급자 청구·해당 시점 단가가 있을 때만 산출. 모델·캐시·처리 항목이 다른 요청을 단일 토큰 단가로 환산하지 않음 |

사용량을 받지 못한 요청은 `미측정`으로 남기고 0으로 채우지 않는다. 생성 요청이 실제로 없었던 로컬 동작과 호출했지만 사용량이 누락된 경우를 구분한다. 측정 로그에는 영상·자막·질문/응답 본문·학생 필기·API 키를 남기지 않는다.

같은 강의·실제 사용 모델·질문·재생 시각·문제 모드로 기존 경로와 실험 경로를 비교하고 순서를 바꿔 측정한다. 작은 부등호 변경, 축·단위, 긴 지문·밑줄, 이미 읽은 판서, 흐린 화면, 정답 표시, 후반 질문을 포함한다. 핵심 정보·시각·답변 품질의 퇴보가 없고 정답·HOLD 노출 0건이며, 재시도 포함 실측 총토큰이 감소한 범위에서만 절감률과 반영 자격을 보고한다. 통과하지 못하면 `baseline`을 유지한다.

현재 생성 모델 토큰과 비용의 절감률은 미측정이다. 기존 필기 내보내기의 로컬 처리 시간 개선은 별도 성능 결과이며 모델 토큰 절감으로 환산하지 않는다. 재현 절차와 구현/실측의 구분은 [Gemini 계측·실험 경로 문서](GEMINI_TOKEN_OPTIMIZATION_2026-11-16.md)를 따른다.

## 7. 선행 조건과 범위 경계

- **시험 환경:** 실제 사용자 평가 전 학생·보호자가 접속할 동일 서비스와 각 역할 계정·기기, 배정된 공개 연습 샘플을 준비한다. 두 컴퓨터의 localhost를 같은 서버로 간주하지 않는다.
- **음성 사용:** 마이크 동의·브라우저 지원과 앱 TTS 또는 외부 스크린리더 동작을 사전 확인한다. 앱 TTS 미지원과 음성 인식 미지원을 구분하고 타자·읽기 영역 대체를 제공한다.
- **원본과 분석:** 기본 영상은 브라우저에 두고 기존의 명시적 동의·권한·임시 분석기 경로만 실제 분석에 사용한다. 샘플·재생용 등록·실제 분석 상태를 구분한다.
- **개인 기록:** 학생 필기·질문 본문을 튜토리얼 분석이나 보호자 현황에 추가하지 않는다. 원본 녹음과 긴 인식 문장은 기본 저장하지 않고 최근 명령 요약은 현재 세션에 둔다.
- **학습 보호:** 0.72 미만의 시각 후보와 문제 모드 정답을 질문 모델 입력·공개 API·UI·TTS·복습·연결 원문에서 차단한다. 동일 정보를 이미 말했으면 기존 `INDEX_ONLY`를 유지한다.
- **비용과 호환성:** 튜토리얼·도움말·상태 확인·재청취에 생성형 모델 호출을 추가하지 않는다. 모델 실험은 기존 `baseline`과 별도의 실측·품질 게이트로 유지한다.

가입·연결·배정 API 자체의 단순화, 학생의 임의 샘플 배정, 운영체제 전체 프로그램 감지, 새 전역 키 가로채기, 학생 필기 AI 작성, 원본 자동 공유·실시간 감시는 이번 첫 버전에 포함하지 않는다. 안내 개선 후에도 특정 인증·연결 단계가 계속 막히면 실제 실패 근거를 갖고 별도 과제로 검토한다.

### 8.2 사용자 평가: 개선 여부를 판단하는 지표

안대 체험 피드백은 초기 조작과 안내의 개선 근거로 사용한다. 실제 시각장애 학생의 사용성과 학습 효과는 별도 평가한다. 참가자 수·중복 응답·기기·체험 빌드가 확인되지 않아 기존 만족도나 성공률은 산출하지 않는다.

실제 학생 5~8명·실제 보호자 3~5명 규모의 초기 파일럿을 제안한다. 모집 규모는 조정하며 전맹/저시력·스크린리더 숙련도·입력 방식·기기 차이를 기록한다. 이 소규모 결과를 전체 사용자 비율로 일반화하지 않는다.

| 평가 질문 | 과업·기록 | 개선 판단 |
| --- | --- | --- |
| 처음 혼자 시작할 수 있는가 | 학생 재생·전체 중지·타자 대체의 성공 인원/시도 인원, 진행자 도움·막힌 위치 | 진행자의 조작 설명이 줄고 핵심 과업 성공이 유지·개선됨 |
| 연결 과정이 이해되는가 | 두 역할의 가입·연결·샘플 배정, 단계별 시간·도움·잘못된 완료 이해 | 막힌 단계와 불필요한 재시작이 줄어듦 |
| 내 명령의 결과를 아는가 | 프로그램이 해석한 동작·성공/실패를 설명하고 오인식을 수정 | 인식과 완료의 혼동이 줄고 타자 대체로 복구 가능 |
| 명령을 잊어도 계속할 수 있는가 | 현재 도움말을 찾아 다음 행동 수행 | 안내를 스스로 찾고 필요한 조작으로 복귀 |
| 안내가 강의와 편집을 방해하는가 | 불필요한 정지·반복 낭독·초점 이동·주관적 부담과 중요한 정보 누락 | 조작 확인이 늘어도 학습 방해와 정보 누락이 증가하지 않음 |
| 다음에도 독립 사용이 가능한가 | 다른 날 짧은 재방문, 보호자 조작 없이 수강 시작·중지·다시 듣기 | 반복 튜토리얼 강제 없이 사용·복구 가능 |

기존 v1.1의 90%는 초기 희망 목표였으며 이번 소규모 파일럿의 확정 통과선으로 쓰지 않는다. 과업별 성공 분자/분모와 개인별 실패 원인을 함께 보고한다. 미해결 제품 결함이 핵심 조작을 막으면 수정 후 재평가한다.

첫 사용은 학습 효과가 크므로 같은 사람에게 현재 방식과 새 방식을 연달아 시켜 단순 시간 차이를 효과로 계산하지 않는다. 첫 사용 조건을 나누거나 난도가 비슷한 다른 과업의 순서를 바꾸고 차이를 기록한다. 보호자·학생의 초기 협력 설정과 학생의 이후 독립 수강도 따로 측정한다.

기록은 익명 참가자 코드·역할·기기·과업·성공·시간·도움·오류 유형 중심으로 한다. 개인 필기·질문·비밀번호·API 키·강의 원본·마이크 녹음은 기본 수집하지 않는다. 참여 동의·중단 선택과 사용 자료의 권한을 확인한다.

## 9. 단계별 출시와 되돌리기

1. **시안 확인:** 짧은 대본·역할 흐름·실제 완료 조건을 먼저 코드와 대조한다. 실제 사용자와의 대본·과업 평가는 별도 일정으로 진행하며, 평가 전 신규 실습은 선택형으로 제공한다.
2. **선택형 평가 빌드:** 새 연습과 공통 도움말을 사용자가 선택해 진입한다. 기존 강의 듣기와 사용법은 계속 이용할 수 있다.
3. **기본 진입 반영:** 필수 회귀와 실제 사용자 과업 평가를 통과한 범위에서 첫 방문 안내를 바꾼다. 기존 사용자의 완료 기록을 일괄 초기화하지 않는다.
4. **후속 확장:** 검증된 상태 단축키부터 추가하고 전체 명령 안내·설명량 선택을 별도로 평가한다.

튜토리얼이 막히거나 새 음성 확인이 조작·재생을 방해하면 새 진입·안내 경로를 끄고 기존 사용법·명령 실행으로 복귀할 수 있게 한다. 안내 진도와 학생 필기·학습 위치를 분리해 복귀 과정에서 개인 데이터를 지우지 않는다. 보호 정책과 오류 회귀를 끄는 방식으로 되돌리지 않는다.

## 10. 다음 착수 단위와 근거
