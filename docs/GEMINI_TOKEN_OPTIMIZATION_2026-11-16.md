# Gemini 사용량 계측과 실험 경로

제출본 기본값은 **기존 전체 분석·전체 검증 경로(`baseline`)**이다. 이번 환경에는 `GEMINI_API_KEY`와 외부 분석 공급자 연결이 없으며 실제 모델 호출을 실행하지 않았다. 실제 총토큰 감소와 모델 품질 동등성을 확인하기 전에는 최적화 경로를 제출본에 적용하지 않는다. 결정적 데모와 HTTP 모의 응답을 실제 영상 분석이나 실측 절감으로 표시하지 않는다.

## 1. 변경 전 기준과 측정

작업 시작 기준은 `2315570fa5dec926bf6c83a05c7a6b2ee1c042ec`이며 당시 추적 파일의 미커밋 변경은 없었다. 기존 미추적 검증 자료는 보존했다. 작업 중 저장소에 추가된 `858df44`, `cf5fabe` 커밋도 되돌리지 않았다. 이후 변경은 그 위에 이어서 적용했다.

기존 경로는 generateContent 전체 영상 탐색 1회와 전체 영상 재검증 1회다. 호환성 경로로 전환하면 Interactions에서 두 단계를 다시 실행한다. 질문은 종전의 강의 문맥을 전송한다. Gemini 모델·키·온도·인증·학생 화면·공개 API 형식은 유지한다.

`app/adapters/usage_metrics.py`는 각 생성 요청의 단계(`analysis`, `verification`, `question`), 요청 모델, 무작위 operation/request ID, 시도 번호, 재시도 여부, 경로, 성공 여부와 다음 카운터만 기록한다.

| 항목 | generateContent | Interactions |
| --- | --- | --- |
| 입력 | promptTokenCount | total_input_tokens |
| 출력 | candidatesTokenCount | total_output_tokens |
| 추론 | thoughtsTokenCount | total_thought_tokens |
| 캐시 | cachedContentTokenCount | total_cached_tokens |
| 총계 | totalTokenCount | total_tokens |

캐시·추론을 공급자 총계에 다시 더하지 않는다. 누락된 값은 `null`이며, 사용량을 하나도 받지 못한 요청은 `미측정`이다. 일부 카운터만 수신해도 누락된 총계를 추정하지 않는다. HTTP·연결·응답 JSON·스키마 오류가 난 시도도 기록한다. 성공은 해당 생성 요청의 파싱 완료를 뜻하며, 공개 가능한 내용이라는 품질 판정은 별도다. 정상적인 HOLD 응답도 토큰을 소비한 요청으로 집계한다.

측정 JSON에는 영상·자막·질문·모델 응답 본문, 원본 URL·파일 ID·사용자 ID, API 키·헤더·오류 본문을 기록하지 않는다. 업로드·폴링·삭제는 생성 요청이 아니며, 기존 임시 Files 삭제 절차를 유지한다.

현재 변경 전후 실측은 다음과 같다. 각 칸의 미측정은 입력·출력·추론·캐시·총토큰 **모두 미측정**이라는 뜻이다.

| 단계 | 변경 전 | 실험 경로 | 비교 결과 |
| --- | --- | --- | --- |
| 1차 전체 탐색 | 미측정 | 미측정 | 입력·프롬프트 유지, 실측 대기 |
| 2차 검증 | 미측정 | 미측정 | 실제 구간 처리·토큰 영향 검증 대기 |
| 질문 | 미측정 | 미측정 | 실제 답변 품질·토큰 검증 대기 |
| 재시도 포함 합계 | 미측정 | 미측정 | 절감률 산출 불가 |

계측만 적용한 시점의 기존 회귀 검사는 API 297 통과/4 제외였다. 이 수치는 토큰 수가 아니다. 현재 연결 상태와 적용 보류 결정은 [측정 상태 JSON](verification/2026-11-16-token-optimization/measurement-status.json)에 남겼다.

## 2. 구간 검증과 응답 축소

`core/verification_plan.py`는 공개 후보 주변 ±5초를 시작값으로 삼아 겹치는 구간을 합친다. 장면 시작·종료가 있으면 해당 범위를 포함하고, 겹치는 발화의 시작·끝까지 넓힌다. 긴 지문·밑줄·이어지는 판서·음성 대조가 필요한 장면은 명시된 전체 장면 범위를 사용한다. 이런 장면의 범위가 없거나, 검증할 자막이 구간 밖에 있거나, 지문 출처 범위가 없거나, 후보 ID가 중복되거나 구간이 너무 많으면 기존 전체 검증으로 돌아간다. 긴 강의의 자막이 전체에 걸쳐 있으면 이 보수적인 대체 경로를 자주 사용할 수 있다.

실험 요청은 원본 file_data와 같은 part에 `videoMetadata.startOffset/endOffset`을 넣는다. 프롬프트에만 시간을 쓰는 방식이 아니다. 원본 영상을 다운로드하거나 재인코딩하지 않고, FPS·해상도를 낮추지 않는다. HTTP 모의 검사는 첫 탐색이 전체 영상이고 두 번째 요청에 실제 구간 필드가 포함되는 것을 확인한다. 공급자가 이를 실제로 적용하고 사용량이 감소하는지는 아직 실측하지 못했다. 지원 거절·형식 오류·자료 모순 검증 누락이면 전체 검증을 재시도하고, 그 비용도 모두 집계한다. Interactions 호환성 경로는 기존 전체 검증을 유지한다.

두 번째 프롬프트의 시각 후보에는 서버가 만든 짧은 ID, 원본 시각과 화면 위치만 보낸다. 1차 판독 문구·수치·해설은 제공하지 않는다. 검증 모델은 화면을 다시 읽고, 다시 읽은 원문·직접 보이는 근거·실제 원본 시각·판독 상태·수정 사항을 반환한다. 서버는 짧은 ID를 기존 observation/component ID로 복구해 두 판독을 비교한다.

기존 자막·지문·밑줄·study_guide의 모순 검증 자료는 필요한 원문으로 보존한다. 네 자료에 대한 명시적인 확인이 없으면 전체 검증으로 돌아간다. 응답 전체를 AnalysisPackageInput으로 다시 생성하도록 요구하지 않는다. 판독이 바뀌거나 확인이 누락되면 출처를 추적할 수 없는 요약·지문·강조 자료를 보류하고, 첫 판독의 annotation을 그대로 재사용하지 않는다. 숫자·부호·부등호·단위 변경 및 삭제, 빠진 구성요소, 불확실한 시각, 근거 누락, 0.72 미만은 기존 구성요소 정책으로 HOLD 처리한다. 실험 경로가 보수적으로 자료를 줄이는 경우가 있어 실제 품질 게이트 통과를 아직 주장하지 않는다.

## 3. 질문 근거 선택과 공개 경계

`core/question_evidence.py`는 전체 강의의 검증된 원문을 검색한다. 현재 화면 질문은 인접한 화면 설명과 발화를 우선 선택한다. 시간 지정·비교·후반부 질문은 강의 전체에서 관련 내용을 찾는다. 처음 160개 발화/100개 화면만 검색하는 제한을 실험 검색에는 사용하지 않는다. 원문을 부분 문자열로 잘라 맞추지 않고, 선택한 원문·문장 ID·문단 번호·원본 시각을 유지한다.

근거가 약하면 탐색 창을 넓혀 강의 전체를 찾는다. 인접 근거로 답하지 못한 모델 응답은 전체 강의 검색으로 한 번 더 시도할 수 있으며 같은 operation ID의 question 재시도로 기록한다. 충분한 원문을 예산 안에 보존할 수 없으면 보류한다. 모델 응답은 선택된 evidence ID, 해당 원문의 정확한 인용, 선택된 시각·문단 번호를 사용해야 한다. 없는 근거나 다른 시각을 지정하면 실행·낭독을 보류한다.

입력 직전 snapshot을 다시 검사해 HOLD·낮은 확신도·문제 모드 정답과 이 내용에 오염된 요약·지문을 제거한다. 알려진 차단 내용을 포함한 질문은 모델로 보내지 않는다. 응답의 제목·본문·근거 등에도 차단 원문이 없는지 검사한다. 낮은 확신도 응답에는 근거·이동 시각·문단을 남기지 않는다. 문제 모드의 최종 정답 요청은 준비된 풀이 방향 안내로 처리한다.

기존 학생 확장의 재생·일시정지·시점 이동·준비된 화면 해설·요약·문단 낭독은 로컬 경로를 그대로 사용한다. 학생 CSS·학생 함수·API 계약·쿠키 인증은 수정하지 않았다. 이 경로에 생성 호출을 추가하지 않았다.

## 4. 동일 조건 실측 재현

1. 직접 제작했거나 분석 권한이 있는 동일 강의를 준비한다. 작은 `<`/`≤` 변화, 그래프 축·단위, 긴 지문·밑줄, 강사가 이미 읽은 판서, 흐린 화면, 정답 표시, 충분히 뒤에 있는 질문 근거를 포함한다. 문제 모드 켜짐/꺼짐을 각각 검사한다. 보호 스트림을 내려받지 않는다.
2. [manifest 템플릿](../scripts/fixtures/gemini-token-benchmark.example.json)을 저장소 밖의 비공개 디렉터리에 복사한다. 파일 위치·동일 질문·재생 시각과 교사가 확인한 필수 원문/금지 원문/시각을 채운다. 빈 oracle 배열과 교체용 문구를 검토하고 `ready_for_live=true`로 바꾼다. 이 manifest는 측정 로그에 복사하지 않는다.
3. 기존 환경변수로 동일 Gemini 모델과 키를 구성한다. 키 값은 명령·로그에 쓰지 않는다. 기본 모델은 기존 `gemini-2.5-flash`이며, 양쪽 경로에서 모델 설정이 같아야 한다.
4. 아래 명령은 **명시적으로 동의한 자체 영상의 임시 업로드와 유료 모델 호출**을 실행한다. AB/BA 순서를 번갈아 실행해 캐시·순서 효과를 한 경로에만 몰지 않는다. 파일 바이트·질문·재생 시각·문제 모드·모델 조건을 동일하게 유지한다. `--quality-artifacts`는 검토용 공개 snapshot/응답을 측정 JSON과 분리해서 저장하는 명시적 선택이다. 이 옵션을 생략하면 검토 본문을 저장하지 않는다. 원본 영상·질문·API 키는 검토 파일에도 복사하지 않는다.

```bash
.venv/bin/python scripts/measure_gemini_tokens.py \
  --manifest /private/tmp/sullivan-token-eval/manifest.json \
  --output docs/verification/2026-11-16-token-optimization/paired-live.json \
  --quality-artifacts /private/tmp/sullivan-token-eval/quality \
  --live --owned-media --repeats 2
```

5. 검토자는 원본 강의와 각 pair의 비공개 검토 파일을 대조한다. 필수 정보, 판독·해설 시각, 답변 정확도, 긴 지문·밑줄, 이미 말한 판서의 INDEX_ONLY, 키보드·리더 흐름을 확인한다. 문제 모드 정답/보류 내용 노출은 API JSON·UI·TTS·복습 자료 각각 0건이어야 한다. 모델의 스스로 매긴 확신도를 사람의 품질 승인으로 취급하지 않는다. 실제 VoiceOver/NVDA 출력과 청취는 사람이 확인해야 한다.
6. 비공개 review JSON에 각 pair의 실제 출력 SHA-256과 판정을 기록한다. 값은 아래 형태이며 모든 품질 항목이 true이고 노출 건수가 0이어야 한다. `*_output_sha256`은 결과 JSON의 값과 일치해야 한다. 내용이 다른 재실행에 검토 승인을 재사용할 수 없다.

```json
{
  "pair-1": {
    "baseline_output_sha256": "검토한 실제 baseline 출력 해시",
    "experimental_output_sha256": "검토한 실제 experimental 출력 해시",
    "required_information": true,
    "reading_and_explanation_times": true,
    "answer_quality": true,
    "long_passage_and_underline": true,
    "spoken_board_index_only": true,
    "keyboard_and_reader": true,
    "held_leaks": 0,
    "answer_leaks": 0,
    "no_regression": true
  }
}
```

7. 공급자를 다시 호출하지 않고 기존 측정에 검토를 결합한다.

```bash
.venv/bin/python scripts/measure_gemini_tokens.py \
  --manifest /private/tmp/sullivan-token-eval/manifest.json \
  --output docs/verification/2026-11-16-token-optimization/paired-live.json \
  --review /private/tmp/sullivan-token-eval/review.json --finalize
```

카운터가 없는 실패/재시도가 하나라도 있으면 완전한 총토큰 비교로 인정하지 않는다. 공급자 총계를 재시도까지 합산하고, 단계별 입력·출력·추론·캐시·총계를 별도로 출력한다. 실제 동일 조건의 완전한 측정에서만 절감률을 산출한다. 자료·시각·금지 원문 oracle 실패를 수동 승인으로 덮을 수 없다. 7개 필수 사례, 품질 승인, 0건 노출, 완전한 총토큰 감소를 모두 충족해야 제출본 반영 자격이 생긴다. 도구는 통과해도 제출본을 자동 전환하지 않는다.

키가 없거나 `--live`를 주지 않으면 네트워크·업로드 없이 `미측정` 보고서만 생성한다. 모의 응답의 토큰 수를 이 보고서의 실제 절감 수치로 사용할 수 없다.

## 5. 회귀 검증 상태

결정적 테스트는 구간 합치기·범위 확대·전체 검증 대체, 실제 HTTP 입력 구조, 첫 판독 비전송, 자료 확인 누락, 숫자/부호/단위 변경·삭제, 시각 불일치, HOLD·정답 차단, 긴 지문·밑줄, INDEX_ONLY, 후반부 검색, 복수 시점, 근거 부족 확대·재시도, 근거 인용과 미측정 게이트를 검사한다. 실제 모델의 OCR·해설·답변 품질은 이 검사로 증명하지 않는다.

브라우저 검사 중 기존 `verify_student_notes.py`에서 강의 ID 변수 `ident`를 DOM ID 반복문이 덮어쓰는 오류를 발견했다. 이후 철회 SQL이 강의 대신 `command-input`을 찾고 있었다. 반복 변수명을 분리하고 UPDATE 영향 행 수 1건을 검증하도록 수정했다. 검증 출력 경로도 분리해 이전 사용자 검증 이미지를 덮어쓰지 않도록 했다. 제품 UI 변경은 없다.

중단 전 전체 검사 및 브라우저 접근성 결과는 [이전 수락 결과](verification/2026-11-16-token-optimization/acceptance-final/results.json)에 보존했다. 아래 재개 작업은 별도 결과 디렉터리를 사용한다. 실제 공급자 연결, 모델 품질, 토큰 감소, 사람의 스크린리더·청취 평가는 여전히 별도로 남아 있다.

## 6. 중단 후 재개 검증

다른 계정에서 중단된 작업을 이어받아 기존 미커밋 코드·문서·검증 자료를 보존했다. 재개 시작 시 API 검사는 340 통과/4 제외였다. 재개 후 다음 사항을 보완했다.

- 구간 재판독은 원래 발화의 ID·시각만 받고, 1차 자막을 보지 않은 상태에서 실제 발화를 다시 듣는다. 모든 발화의 원본 범위·원문·0.72 이상 확신도를 확인한 뒤에만 자료 모순 검증으로 넘긴다. 누락·시각 불일치·불확실한 발화는 기존 전체 검증으로 대체한다. 화면과 같은 장면의 음성을 독립된 진실로 취급하지 않는다.
- 독립 재판독과 텍스트 자료 모순 검증은 별개 요청으로 집계한다. 계획된 자료 검증은 재시도가 아니며, 실패 후 전체 검증·호환성 경로는 재시도로 집계한다. 요청 번호는 각 단계 안에서 중복 없이 증가하며 모든 요청의 사용량을 합산한다.
- 구성요소의 화면 근거가 비어 있으면 관련 지문·밑줄·학습 자료도 보류한다. 오래되거나 변형된 snapshot의 비공개 사유도 질문 입력과 모델 출력의 차단 대상에 포함한다.
- 비교는 환경변수뿐 아니라 실제 사용량 기록의 단계별 모델도 대조한다. 모든 강의 사례와 AB/BA 반복 쌍이 완료되어야 제출 가능 판정을 허용한다. 다른 모델의 대체 호출, 미측정 실패, 일부 사례만 끝난 결과로 절감률을 주장하지 않는다. 단계별 합계는 `gate.stage_comparison`에 제공한다.

[재개 검증 결과](verification/2026-11-16-token-optimization/resumed/results.json)와 [최신 미측정 보고서](verification/2026-11-16-token-optimization/resumed/measurement-status.json)를 함께 확인한다. `bash scripts/verify_all.sh` 통과, API 351 통과/4 제외, 제출 패키지 15 통과를 확인했다. 제외된 4건은 별도 PostgreSQL 시험 DB가 필요한 검사다. 재개 전보다 API 검사가 11건 늘었으며 제거한 검사는 없다.

실제 Chromium에 설치한 두 확장에서 보호자 학생 만들기 → 샘플 배정, 학생 수강·노트·키보드 흐름을 검사했다. 별도 시연 검사 9항목도 통과했다. 검사한 총 20개 화면 상태의 axe 4.14.0 위반은 0건이며, 1280px·390px 캡처는 `resumed/student-notes/`와 `resumed/submission-flow/`에 보존했다. 업로드된 자체 제작 샘플의 원본 미디어 POST는 0건이다. 브라우저 검사는 실제 Gemini 분석이 아닌 사전 준비 샘플을 명시한다. 리더 live region으로 한 번 전달되고 앱 TTS가 중복 호출되지 않는 경계는 검사했지만, 실제 VoiceOver/NVDA 청취 및 네이티브 TTS 시작·종료는 검증하지 못했다.

부등호·축/단위·긴 지문/밑줄·이미 말한 판서·흐린 화면·정답·후반 질문은 결정적/모의 HTTP 회귀 검사 범위에서 통과했다. 이 범위의 정답·HOLD 원문 노출 검사는 실패 0건이다. 실제 모델의 정보 누락·시각 정확성·답변 동등성을 입증한 결과는 아니다.
