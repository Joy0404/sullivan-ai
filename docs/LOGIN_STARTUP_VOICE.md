# 로그인 첫 음성 수정

2026년 11월 4일

## 원인과 변경

새 Chromium 세션에서 초점은 ‘학생 로그인’에 있지만 Web Speech가 실제로 `not-allowed` 오류를 반환하는 것을 확인했습니다. 이전 검사는 요청한 문구만 기록해 이 차단을 놓쳤습니다. 음성 요청을 보낸 상태와 실제 시작·완료·실패 상태를 구분하도록 수정했습니다.

로컬 Mac 실행기는 첫 ‘학생 로그인’ 안내에 시스템의 한국어 음성을 사용합니다. 브라우저의 첫 자동 음성에 의존하지 않으며, 초점은 그대로 유지합니다. 나머지 버튼 안내는 기존 브라우저 음성을 사용합니다.

- 첫 진입·새로고침마다 시작 안내를 한 번 실행합니다.
- Tab·Shift 이동, 보호자 선택, 음성 안내 해제, 로그인 완료, 창 비활성화·이탈 시 시작 안내를 취소합니다.
- 취소한 프로세스가 끝난 뒤 다음 버튼을 안내합니다. 늦은 응답은 초점·현재 로그인 상태를 바꾸지 않습니다.
- 시스템 음성과 브라우저 음성을 동시에 시작하지 않습니다. 불확실한 시스템 요청은 중지를 확인한 후에만 브라우저로 전환합니다.
- 첫 안내의 일반 시작·종료 메시지를 스크린리더 상태 영역에 반복해서 알리지 않습니다. 필요한 오류 안내는 유지합니다.

시스템 음성 경로는 **실행기가 명시적으로 켠 로컬 Mac·루프백 요청**에만 적용됩니다. 문구는 ‘학생 로그인’으로 고정되어 로그인 이름·비밀번호나 임의 텍스트를 읽지 않습니다. 다른 운영체제·호스팅 서버에서는 기존 브라우저 음성을 사용합니다. Chromium의 음성 제한에 관한 배경은 [Chrome 자동 재생 정책](https://developer.chrome.com/blog/autoplay)을 참고할 수 있습니다.

## 검증

- 전체 검사 **116개 통과, 4개 건너뜀**. JS 문법 검사 통과.
- 첫 방문·새로고침: 실제 새 Chromium 창과 실행 중인 로컬 Mac 서버에서 **사용자 활성화 없이 시스템 음성 프로세스 완료**, 학생 로그인 초점 유지, 브라우저 음성 중복 요청 0회를 확인했습니다.
- 실제 한국어 합성으로 약 **0.96초의 무음이 아닌 오디오**를 생성했습니다. 사람이 스피커 출력을 들었거나 VoiceOver·NVDA 낭독을 확인한 검사는 아닙니다.
- 임시 DB·모의 프로세스 검사: Tab 취소, 보호자 전환 후 무음, 창 이탈 취소, 로그인된 페이지의 시작 안내 생략, 응답 유실·중지 실패 후 오래된 상태 메시지 방지 통과.
- API 검사: 로컬 모드·출처·요청 헤더 제한, 고정 문구, 중복 실행 억제, 시작보다 먼저 도착한 취소, 실행 중 취소 통과.
- 기존 버튼 순서·Shift 이전 이동·음성 중 강의 일시정지·로그인/배정 회귀 검사 통과. 키보드와 실시간 안내 전문 검토에서 남은 지적 사항은 없습니다. 이는 변경 범위의 소스 검토입니다.

결과: [시작 흐름 회귀 검사](verification/login-startup-results.json), [실제 로컬 Mac 실행](verification/login-startup-native-results.json).
