# Sullivan AI 해커톤 시연 시나리오·대본

**목표 영상 길이 2분 45초(165초).** 3분 제한에서 15초 여유를 둔다. 아래 대본은 내레이션이며, 앱 음성이 나오는 동안 발표자는 말을 멈춘다. 실제 읽는 속도와 화면 전환을 포함해 한 번 리허설하고 최종 재생 시간을 확인한다. 이 문서는 촬영안이며 녹화·제출을 완료했다는 뜻은 아니다.

전달할 한 문장: **“강사가 말하지 않은 화면 정보를 보완하고, 학생이 자기 속도로 강의를 이어가게 돕습니다.”**

## OBS 녹화 준비

- 권장 출력: 1920×1080, 30fps. 이는 촬영 제안이며 대회 필수 규격으로 확인한 값은 아니다. 제출 형식·용량 조건이 따로 있으면 그 조건을 우선한다.
- 장면 3개: `01 소개`(소개 페이지), `02 보호자`(준비실/검토), `03 학생`(학생 수강 화면). 브라우저 창을 동일한 크기로 맞춘다. 긴 입력·로그인·대기 장면은 녹화 밖에서 준비한다.
- 보호자와 학생을 동시에 준비하려면 Chrome 일반 창과 시크릿 창처럼 쿠키가 분리된 창을 사용한다. 같은 프로필의 두 탭은 로그인 쿠키를 공유한다. 계정·최초 사용법 확인은 촬영 전에 마친다.
- macOS에서는 `macOS Screen Capture`의 창 또는 애플리케이션 캡처로 브라우저만 잡는다. macOS 13 이상은 이 소스로 앱 오디오도 캡처할 수 있다. 마이크 입력은 별도 소스로 추가하고 10초 시험 녹화에서 발표자 음성·앱 음성이 둘 다 들리는지 확인한다. 같은 앱 소리를 화면 캡처와 오디오 캡처 두 곳에서 중복으로 잡지 않는다. [OBS 화면 캡처 안내](https://obsproject.com/kb/macos-screen-capture-source), [OBS macOS 오디오 안내](https://obsproject.com/kb/macos-desktop-audio-capture-guide).
- OBS 안내에서 권장하는 녹화 컨테이너인 MKV로 저장하고, MP4가 필요하면 `파일 → 녹화 리먹스(Remux Recordings)`로 변환할 수 있다. [OBS 녹화·리먹스 공식 안내](https://obsproject.com/kb/standard-recording-output-guide).
- 발표자 음성 권장 피크는 약 -12~-6dB, 앱 음성은 겹치지 않게 조절한다. 헤드폰을 쓰고 알림·메신저·개인 계정/비밀번호 노출을 정리한다. BGM은 생략하는 편이 음성 접근성 시연에 적합하다.

## 촬영 전 앱 준비

1. 샘플 서버: `bash START_LOCAL.command --sample --no-open`. [소개](http://127.0.0.1:8770/intro/), [앱](http://127.0.0.1:8770/).
2. 보호자 계정과 식별 가능한 체험 학생 한 명을 준비한다. 학생 창에는 학생으로 미리 로그인하고 최초 사용법 확인을 끝낸다. 학생에게 영상이 보이지 않으면 다음 배정 뒤 ‘강의 듣기’로 목록을 새로 읽는다.
3. 보호자 창의 ‘샘플로 연습하기’를 펼쳐 과학 샘플을 준비한다. 이미 배정한 같은 샘플을 반복해서 새로 배정하지 않도록 촬영용 목록을 정리한다.
4. 학생 창에서 ‘자동 정지·해설’을 켠다. 발표자가 Tab 설명을 하는 동안 중복 앱 안내가 끼지 않도록, 촬영에 필요한 경우 포커스 앱 음성은 꺼두고 해설 음성은 유지한다.
5. 과학 샘플은 **0:43**에 첫 `DESCRIBE_AT_BREAK` 해설이 있다. 테스트 재생에서 0:40 근처부터 재생해 실제 자동 정지와 음성을 확인한다. 영상 위치·해설 버튼의 동작을 미리 리허설한다. 자동 정지 장면을 찍을 때는 시작 후 키를 계속 누르지 않는다.
6. ‘지문·문단 듣기’의 첫 문단, ‘원하는 내용 찾기’의 `주계열성`, 보호자 ‘해설한 이유’의 보류 항목 위치를 미리 확인한다. 안전 검토 화면은 별도 컷으로 준비해도 된다.
7. 아래쪽 고정 바가 중요한 내용을 가리지 않도록 창 크기와 OBS 캡처 영역을 맞춘다. 확대가 필요하면 앱의 실제 화면을 확대하고, 장면마다 배율을 급하게 바꾸지 않는다.

| **2:35–2:45** | `01 소개` 또는 마지막 정지 화면. 제목 자막: `대신 풀어주는 AI보다, 스스로 이어가는 학습`. | “설리번 AI는 정답을 대신 주기보다, 학생이 강의를 스스로 이어가도록 돕습니다. 실제 사용자 검증을 준비하는 시제품입니다.” |

## 자막·촬영 메모

- 영상 시작과 실제 기능 컷에서 `사전 준비된 샘플 결과 · 새 영상 분석 아님`을 읽을 수 있게 유지한다. 기존 샘플 표시를 잘라내지 않는다.
- 자동 정지 컷은 앱이 실제로 정지하고 음성을 낸 녹화만 사용한다. 연결 문제로 자동 정지를 재현하지 못했다면 수동 버튼 컷에 ‘자동으로 멈췄다’는 대사를 붙이지 않는다.
- 대체 컷: ‘현재 화면 다시 설명’을 직접 눌러 실제 해설을 보여주고, 대사를 **“필요할 때 현재 화면 해설을 다시 들을 수 있습니다.”**로 바꾼다. 자막도 `직접 선택한 화면 해설`로 맞춘다.
- 별도 컷을 이어 붙이는 경우 실제 입력·대기만 줄이고, 샘플을 새 영상 실시간 분석처럼 보이게 편집하지 않는다.
- 이 서버의 샘플 모드는 외부 유료 분석을 실행하지 않는다. `Gemini가 지금 새 영상을 분석했습니다`, `VoiceOver/NVDA 검증 완료`, `효과 입증`은 이 시연 대본에 넣지 않는다.
- 원본 강의 영상·음성을 제출 영상에 담을 이용 권한을 확인한다. 확인하기 어려우면 원본 영역·원본 음성 녹화를 제외하고 앱 UI·해설과 발표자 설명으로 구성한다. 이 경우 자동 정지의 전후 상태가 실제로 보인 컷만 사용한다.
- 시간이 밀리면 계정 생성·로그인·긴 개념 구간 재생을 줄인다. 핵심인 **해설 → 문단 탐색 → 학생의 선택**은 남긴다. 제목·엔딩을 포함한 최종 파일 재생 시간이 3분 이내인지 확인한다.

## 제출 직전 점검

- [ ] 영상 길이 3분 이내. 목표 2:45, 여유 포함 2:55 안쪽.
- [ ] 발표자·앱 음성이 둘 다 또렷하고 겹치거나 두 번 들리지 않는다.
- [ ] 글자·시각·밑줄·보류 표시가 전체 화면으로 보아도 읽힌다.
- [ ] 비밀번호·개인 알림·실제 학생 정보가 노출되지 않는다.
- [ ] 샘플 고지, 실제 사용자 검증 전이라는 설명이 남아 있다.
- [ ] 최종 파일을 처음부터 끝까지 재생하고, 별도 제출 형식·용량 조건도 확인했다.
