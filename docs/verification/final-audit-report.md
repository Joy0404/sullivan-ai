# T0~T6 최종 재검사

**판정: 완료 승인 보류.** 기본 기능·권한·재생 검사는 통과했으나, T3에서 화면과 실제 분석 요청이 달라지는 P1 오류 1건을 재현했다. 이 오류를 먼저 고쳐야 한다. 그 밖에 회귀 검사 유지보수, 가이드 이미지, 보호자 글자 크기와 비동기 안내 문맥을 보완해야 한다. 앞선 ‘모두 완료’ 보고를 이 판정으로 정정한다.

- 검사 대상: `Develop` **48b3ac10c459b53076294376122e63d235dd1dee**. 검사 시작 시 로컬 HEAD와 origin/Develop 일치.
- 변경 비교 기준: 작업 시작 직전 `36ef70b`. 플레이북의 더 오래된 기준 커밋 이후 이미 들어온 자동 재생 수정은 기존 구현으로 구분했다.
- 방법: 원본 코드 비교, 전체 검사 재실행, 원본 브라우저 검사 실행, 새 임시 계정에서 키보드·권한·3초 재생 검사, 접근성 전문가 6종 독립 검토.
- 모든 런타임 검사는 임시 DB와 가상 계정을 사용했다. 외부 요청은 차단했으며 실제 유료 분석·사용자 DB·원본 영상 전송은 수행하지 않았다.

## 1. P1 — 다시 연 마법사가 숨겨진 영상 링크를 분석 요청에 포함한다

**위치:** [role-portal.js:379](../../apps/web/role-portal.js#L379), 선택값 처리 342~348행과 요약 340행.

재현 순서:

1. 강의 등록 2단계에서 ‘영상 링크’를 고르고 URL과 보조 TXT를 입력한다.
2. 분석 동의를 체크하고 테스트용 체험 비밀번호를 입력한다.
3. 상단 경로로 준비실에 돌아갔다가 다시 ‘내 강의 자료 준비’를 연다.
4. 마지막 확인 단계로 이동해 제출한다.

`wizard-reset`은 보조 자료가 있다는 이유로 출처를 `link`에서 `file`로 바꾼다. `choose(..., false)`는 원래 URL·체크된 동의·체험 비밀번호를 유지하면서 해당 조작부를 숨긴다. 확인 요약의 자료는 **‘학습자료만 준비’**라고 표시되지만, 제출 시 기존 URL과 `request_analysis:true`, `analysis_consent:true`가 `/video-link` 요청에 포함된다. 실제 분석이 설정된 환경에서는 요약과 다른 영상 분석이 실행될 수 있다.

독립 브라우저에서 설정된 분석 환경의 health 응답만 모의 제공하고, 실제 분석 요청은 브라우저에서 가로채 중단했다. 공급자 호출은 없었다.

**권장 수정:** 명시적으로 고른 출처를 재진입 때 유지하고, 재추론이 필요하면 영상 파일 → URL → 보조 자료 순으로 판별한다. 활성 출처·요약·동의 표시·제출 필드가 항상 일치하도록 정규화한다. 링크+TXT → 준비실 → 재진입 → 제출의 회귀 검사를 저장소에 추가한다.

근거: [출처·숨김·요약·제출 값](final-audit/wizard-reset-results.json), `FORMS-WIZARD-RESET-SOURCE` 전문 검토.

## 2. P2 — 저장소 원본 브라우저 검사 두 개가 실패한다

- [verify_keyboard_navigation.py:29](../../scripts/verify_keyboard_navigation.py#L29): ‘내 강의 자료 준비’에서 뒤로 이동하면 예전 학생 생성 버튼에 도달한다고 단정한다. 현재 DOM의 Tab 순서와 맞지 않아 5초 뒤 실패한다.
- [verify_roles_browser.py:100](../../scripts/verify_roles_browser.py#L100): 예전 연속 폼처럼 자료를 넣고 제출한다. 새 마법사의 출처 선택·단계 이동이 없어서 `#analysis-overlay` 대기에서 30초 뒤 실패한다.

이번 검사에서는 테스트 내용은 바꾸지 않고 **출력 경로만 임시 폴더로 변경해** 두 실패를 재현했다. 기존 작업은 임시 적응본으로 나머지 검사를 통과시켰지만, 그 갱신은 저장소의 검사 스크립트에 반영되지 않았다. `verify_all.sh`는 이 두 브라우저 스크립트를 실행하지 않으므로 기본 검사의 녹색 결과만으로 이 공백을 알 수 없다.

**권장 수정:** 현재 구조에 맞는 조작만 갱신하고 기존 학생·키보드 검증문을 유지한다. 1번 재진입 오류와 3초 정지 검사도 재실행 가능한 회귀 검사에 포함한다.

근거: [키보드 원본 실패 로그](final-audit/keyboard.log), [역할 원본 실패 로그](final-audit/roles.log).

## 3. P2 — 사용 가이드 이미지가 최종 화면과 다르다

**위치:** [guide/index.html:73](../../apps/web/guide/index.html#L73), 80행 및 `intro/img/guardian-prepare.png`, `guardian-review.png`.

4단계 본문은 3단계 마법사를 설명하지만 이미지는 단계 표시·다음 버튼이 없는 예전 긴 폼이다. 결과 확인 이미지에도 T4 변경 전 ‘접근성 복습’ 제목이 남았다. 이미지를 보고 따라가는 보호자가 현재 조작을 찾기 어렵다.

**권장 수정:** T3/T4 최종 UI로 준비·결과 이미지를 다시 촬영하고 캡션·크기·대체 텍스트를 함께 확인한다. 다른 보호자 안내 이미지도 최종 UI와 대조한다.

근거: [이미지·제목 검토](final-audit/alt-text-headings.json).

## 4. P2 — 보호자 화면의 일부 글자가 14px로 남는다

**위치:** [workspace-design.css:183](../../apps/web/workspace-design.css#L183).

보호자 글자 크기 재정의에서 `b`, `time`, `em`이 빠져 `.concept-meta b`, `.concept-meta time`, `.sentence > em`이 320/390/1280px 모두 **14px**로 계산됐다. 플레이북 6절의 보호자 본문 18px 이상 요구를 충족하지 못한다. 측정한 색 대비는 통과했다. 글자 크기 자체를 WCAG 위반으로 단정하지는 않는다.

**권장 수정:** 해당 요소를 보호자 전용 18px 규칙에 포함하고 작은 화면·확대에서 다시 확인한다.

근거: [실측 JSON](final-audit/visual-runtime-evidence.json), [대비 전문 검토](final-audit/contrast-master.json).

## 5. P2 보완 — 여러 학생의 학습 현황 안내가 누구의 결과인지 말하지 않는다

**위치:** [role-portal.js:209](../../apps/web/role-portal.js#L209), 성공·빈 결과·오류 안내 222~224행.

학생 두 명의 학습 현황을 펼친 뒤 다른 조작으로 이동하고 두 요청이 서로 다르게 끝나면, polite 상태 안내는 ‘아직 배정된 강의가 없습니다’, ‘학습 현황을 불러오지 못했습니다’만 전달한다. 메시지에 학생 이름이 없어 어느 학생의 결과인지 구분하기 어렵다.

**권장 수정:** 불러오기·성공·빈 결과·오류 메시지에 학생 이름을 넣는다. 기존 지속적인 `role=status` 노드는 유지한다.

DOM·Chrome 접근성 트리·동시 응답으로 문맥 누락을 확인했다. **확신도 중간:** 실제 VoiceOver/NVDA 낭독은 검증하지 않아 WCAG 4.1.3 최종 적합성 판정은 남아 있다.

근거: [동시 조회 결과](final-audit/sullivan-aria-concurrent-results.json), [라이브 영역 전문 검토](final-audit/live-region-controller.json).

## 기존 코드에서 확인한 추가 한계

아래는 T0~T6 이전 코드와 동일한 동작이므로 새 리스킨 회귀와 구분한다.

- 분석 완료 표시 100%의 750ms 지연 중 취소하면, 기존 포커스 복원 코드가 아직 disabled인 제출 버튼을 복원하지 않고 참조를 지워 포커스가 BODY에 남는다. 다음 Tab은 하단 실행 정보로 이동했다. [role-portal.js:690](../../apps/web/role-portal.js#L690), [재현](final-audit/final-forms-edge-results.json).
- 샘플 바로 배정 중 진행 문구가 일반 p에만 표시되어 완료 전에는 상태 낭독이 없다.
- 기존 파일 교체/URL 편집 시 체크된 분석 동의 유지, 로그아웃 후 비어 있는 URL에 ‘링크 입력됨’ 표시가 남는 동작이 있다. 전문 검토 notes에 기록했다.

## 한계와 후속 판정

실제 VoiceOver/NVDA·사용자 실사용·외부 YouTube·실제 유료 분석은 검사하지 않았다. Postgres 전용 기존 테스트 4개는 환경 미설정으로 건너뛰었다. 단위·정적·axe 통과는 위의 수동 재현 오류를 상쇄하지 않는다.

접근성 6종 원본은 [전문 검토 통합 보고서](final-audit-accessibility.md)와 [원본 JSON](final-audit/)에 있다. 원본 지적 6개 중 브라우저 검사 2개를 하나의 검사 유지보수 항목으로 묶어 위의 5개 항목으로 정리했다. 자동 집계 점수·등급과 별개로 serious 오류가 있어 완료 승인을 보류한다.

수정 우선순위는 **1번 출처/제출 불일치 → 원본 브라우저 검사 갱신·회귀 추가 → 안내 이미지·글자 크기·상태 문맥 보완**이다. 이번 작업은 검사와 증거 기록이며 제품 수정은 포함하지 않는다.
