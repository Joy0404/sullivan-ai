## P2 — 이전 보호자의 401 응답이 새 학생 로그인 화면을 초기화한다

위치: [role-portal.js:17](../../apps/web/role-portal.js#L17), 진행 현황 요청/응답 처리 211~224행.

재현:

1. 보호자로 학습 현황을 펼치고 GET progress 응답을 지연한다.
2. UI에서 로그아웃한 뒤 학생으로 로그인하고 학생 홈 로딩·로그인 제출 완료를 기다린다.
3. 이전 보호자 요청을 401로 완료한다.

완전히 로그인된 학생의 `Portal.user`가 null, 역할이 signed-out으로 바뀌고 포커스는 로그인 버튼으로 이동했다. 같은 시점 `/local/me`는 전후 모두 **200, 동일 학생**을 반환했다. 페이지 오류는 없었다.

공통 `request()`가 응답의 인증 문맥을 확인하기 전에 `signedOut()`을 호출하기 때문에 진행 현황 콜백의 사용자/DOM 검사가 실행될 때는 이미 화면이 초기화됐다. 공통 처리 자체는 기존 코드이며, T5의 비동기 조회 경로가 이 경합을 노출한다. 최근 출처/학생 이름 수정에서 새로 만든 회귀로 분류하지 않는다.

권장 수정: 요청 당시 인증 세대를 저장하고 현재 세대가 같은 경우에만 401의 전역 로그아웃 처리를 적용한다. 역할 전환 시 이전 조회를 무효화/취소한다. 이전 401 뒤 새 로그인 유지와 현재 세션 401 처리 둘 다 회귀 검사한다.

근거: [로그인 안정화 후 대조 결과](reaudit-312a607/stale401-results.json), [전문 검토](reaudit-312a607/live-region-controller.json).

## P2 — 새 가이드 복습 이미지의 고정 바가 내용을 가린다

위치: [guide/index.html:80](../../apps/web/guide/index.html#L80), [guardian-review.png](../../apps/web/intro/img/guardian-review.png).

새 962×1240 PNG의 약 y820~900에 ‘이 강의를 학생에게 제공’ 고정 바가 들어가, 아래 두 카드 ‘강사가 강조한 문장’·‘다시 볼 핵심 구간’의 첫 항목을 가린다. 작은 화면 가이드에서도 같은 부분이 가려진 이미지로 표시된다. 실제 결과 UI의 포커스 가림 회귀가 아니라 촬영 결과물 문제다.

권장 수정: 충분히 큰 뷰포트에서 고정 바가 카드 캡처 영역 밖에 오도록 다시 촬영하고 네 카드의 첫 항목까지 눈으로 확인한다. 변경된 자연 크기에 맞춰 HTML 속성도 맞춘다.

근거: [이미지 전문 검토](reaudit-312a607/alt-text-headings.json). 새 마법사 3장의 이미지/캡션/대체 텍스트 및 가이드 이미지 10개의 실제 크기는 일치한다.

## P3 — 동명이인 학생 카드·조회 안내를 구분하기 어렵다

위치: [role-portal.js:201](../../apps/web/role-portal.js#L201), 조회 안내 209/222/224행.

서로 다른 로그인 이름 `audit.student.a`, `audit.student.b`를 가진 학생 두 명에게 같은 표시 이름을 주면, 카드 제목·학습 현황의 접근성 설명·진행 메시지 모두 같은 이름만 표시한다. 두 카드에는 로그인 이름이 없어 어느 계정인지 직접 구분할 수 없다. 다른 이름의 학생에 대해서는 이전 문맥 보완이 정상 작동한다.

권장 수정: 카드 제목과 상태 안내에 `이름 (로그인 이름)`을 사용한다. 실제 화면과 접근성 설명에서 같은 고유 식별 표현을 유지한다. 동명이인 회귀 사례를 추가한다.

이는 표시 식별성의 남은 한계로, 백엔드가 다른 학생 정보를 반환했다는 뜻은 아니다. 실제 스크린리더 낭독은 검사하지 않았고 직접 WCAG 위반으로 단정하지 않는다.

근거: [동명이인 DOM·접근성 트리·동시 안내](reaudit-312a607/aria-live-results.json), [ARIA 검토](reaudit-312a607/aria-specialist.json).
