# T5 권한·정보 노출 검토

신규 `GET /local/students/{ident}/progress`는 기존 `require(request, 'guardian')` 인증·역할 검사를 먼저 실행한다. 인증 방식을 바꾸지 않는다는 작업 제약에 따라 기존 공통 검사 함수를 그대로 사용한다. 학생 식별자를 받는 SQL은 현재 보호자의 학생인지 확인하고, 실제 강의 조회에도 강의 소유자 조건을 추가한다. SQL 값은 모두 매개변수로 바인딩한다.

허용된 응답은 전용 Pydantic 모델에 명시한 학생 ID, 강의 ID·제목·과목, 저장 위치, 밑줄·북마크·메모 개수, 저장 시각뿐이다. 메모 본문·북마크 설명·밑줄 텍스트·원본 progress payload는 반환하지 않는다. 메모는 기존 저장 모델이 강의당 문자열 하나이므로 공백이 아닌 메모의 존재를 0/1개로 표시한다. 개수와 위치가 없는 옛 기록은 0, 저장 시각이 없거나 유효하지 않으면 null이다. GET은 기록을 보정하거나 갱신하지 않는다. 기존 PUT은 서버 UTC 저장 시각만 추가하며 요청 필드는 그대로다.

브라우저에서는 DOM 생성 및 `textContent`를 사용한다. 학생별 펼침에서 지연 조회하며, 완료 시 현재 보호자 ID·역할과 DOM 연결 여부를 다시 검사한다. 기존 응답 캐시 금지와 인증 쿠키 정책을 유지한다. 새 공급자 호출이나 미디어 전송은 없다.

회귀 검사는 다른 보호자 403, 학생 본인 호출 403, 미인증 401, 정상 소유자 개수·내용 비공개·GET 무변경·배정 철회, 옛/잘못된 기록 호환, 잘못 연결된 다른 보호자 강의 제외를 확인한다. T5 범위에서 남은 차단 결함은 발견하지 않았다. 실제 운영 배포나 저장소 전체 보안 감사 결과를 의미하지 않는다.

적용한 스킬: `security-best-practices`의 FastAPI AUTH/AUTHZ/VALID/RESP/INJECT 지침과 JavaScript 일반 웹 XSS 지침.
