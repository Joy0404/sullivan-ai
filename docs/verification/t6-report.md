### 원인과 수정 범위

기존 정규식 `[a-zA-Z0-9_.-]{3,60}`은 현재 Chrome의 HTML pattern 정규식에서 문자 클래스의 이스케이프되지 않은 하이픈 때문에 콘솔 오류를 발생시켰다. 분리된 Chrome 문서에서 기존 패턴 오류를 재현했다. 두 HTML pattern만 `[a-zA-Z0-9_.\-]{3,60}`으로 고쳤다. 서버의 허용 문자나 인증 방식은 바꾸지 않았다.

자동 재생의 원인은 CUED/UNSTARTED/ENDED인 YouTube 플레이어에서 저장 위치를 `seekTo`로 복원하면 재생이 시작되는 동작이었다. **기존 커밋 `46e9c09`가 이미** `cueVideoById`로 복원하고 명시적 재생 전에는 대기하도록 수정했다. 로컬/직접 영상도 이미 autoplay를 끄고 pause한 뒤 위치를 복원한다. 이번에는 해당 코드를 다시 수정하지 않고 회귀 검증했다.

각 경로에서 Enter로 처음 열기와 Space로 저장 위치 복원을 실행했다. YouTube 0/92,000ms, 암호화 브라우저 원본 0/200ms, 직접 영상 0/200ms 모두 **3,103~3,104ms 후 위치가 정확히 같고 playing=false**였다. YouTube 진입 로그는 cue만 있고 play/seek 호출은 없다. 화면도 ‘강의 일시정지’이며, 이후 재생 버튼을 직접 누르면 시작·정지가 작동한다.
